# 国際電話ブロック / Intl Call Blocker

Android 端末で **国際電話を完全にシャットアウト**するアプリ。
着信は呼び出し音が鳴る前に切り、発信は回線に載る前に止める。

- 国際着信の拒否（`+81` 以外の国番号）
- 非通知・公衆電話・番号不明の着信の拒否
- 国際発信の抑止（`010` / 事業者選択番号 + `010` / `+国番号`）
- 例外を通す許可リスト（完全一致・前方一致）

---

## なぜ Android だけなのか

**iOS では原理的に作れない。**

iOS の着信ブロックは CallKit の Call Directory Extension が唯一の手段で、これは
**電話番号を 1 件ずつ列挙したリスト**しか登録できない。「`+81` 以外を全部」のような
前方一致・ワイルドカードの指定手段が API に存在しないため、「国際電話を全部止める」は
番号を全列挙しない限り実現できない（＝実現できない）。

Android は `CallScreeningService` で着信ごとに番号を見てその場で可否を決められる。
これが正規の API として提供されているので、本アプリはこれを使う。

---

## 動作の前提: 「役割（Role）」を取得しないと 1 件も遮断されない

このアプリは自力で通話に割り込めるわけではない。Android から次の役割を
与えられている間だけ、通話の前段に呼ばれる。

| 役割 | 何が効くようになるか | 無いとどうなるか |
|---|---|---|
| `ROLE_CALL_SCREENING` | 国際着信・非通知の拒否 | 着信の遮断が**一切効かない** |
| `ROLE_CALL_REDIRECTION` | 国際発信の抑止 | 発信の抑止が**一切効かない** |

- 役割は **端末内で 1 アプリしか保持できない**。他の迷惑電話対策アプリが同じ役割を
  持っている場合、そちらを解除しないと取得できない。
- 付与を強制する方法は無く、利用者が OS のダイアログで拒否すれば取得できない。
- アプリ起動時のトップ画面に取得状況を最初に出しているのはこのため。
  設定をいくら入れても役割が無ければ何も起きないので、そこを見落とすと
  「設定したのに国際電話が鳴る」という最悪の誤解になる。

---

## 判定のしかた

判定は `core` モジュールに閉じている（Android 非依存の純 Kotlin）。
`CallScreeningService` / `CallRedirectionService` はその結論を実行するだけの薄い層。

### 判定順序

この順序自体が安全性の要になっている。

1. **緊急通報** — `110` / `118` / `119` / `112` / `911`。設定にも許可リストにも
   関わらず、発着信ともに**必ず通す**
2. **MMI / USSD コード**（発信）— `*#06#` などを横取りしない
3. **許可リスト** — 一致すれば通す
4. **非通知・番号不明** — 設定に従う
5. **国際** — 設定に従う（着信・発信で別設定）
6. **書式不明** — 設定に従う（既定は通す）
7. それ以外（国内）— 通す

### 「国際」の判定

- `+` 付き … 国番号が `81` で始まれば国内、それ以外は国際
  E.164 の国番号は接頭辞符号なので、`81` で始まるかどうかだけで一意に判定できる
  （国番号表は判定には使わず、ログ表示にのみ使う）
- `010…` … 国際発信プレフィックス。剥がした先の国番号で判定する
  （`010` + `81` は宛先が日本なので国内扱い）
- `0033010…` `001010…` `005345010…` … 事業者選択番号 + `010`。
  事業者番号は 3〜6 桁とまちまちなので、**桁数を総当たりして** `010` を探す
  （貪欲マッチで 1 通りだけ試すと桁数違いを取り逃がす。実際にこのバグを踏んだ）
- `0…` … 国内
- 3〜4 桁 … 国内特番（`117` `171` `189` など）
- それ以外 … 書式不明

### 入力の正規化

`tel:` / `sip:` URI、全角数字（`０９０－…`）、括弧・ハイフン・ドット、
ポーズ文字（`,` `;` `p` `w`）以降の切り捨てを吸収してから判定する。

---

## 分かった上で受け入れている限界

- **発信者番号は偽装できる。** 国際発信を国内の番号に見せかけた着信は、
  端末に届いた番号だけでは見分けられない。このアプリは端末に届いた番号で判定する。
  通信事業者側の対策（STIR/SHAKEN 等）を代替するものではない。
- **判定の基準は日本の番号計画に固定。** `+81` を自国、`010` を国際発信プレフィックス
  として扱う。海外の SIM で使う場合はこの前提が合わない
  （`core/DialPlan.kt` を差し替えれば判定全体が追随する作りにはしてある）。
- **`00` 始まりで `010` を伴わない番号は「書式不明」**。既定では通す。
  厳しくしたい場合はトップ画面の「書式不明の番号も拒否」を有効にする
  （取りこぼしは減るが、正当な国内着信が落ちる可能性がある）。
- 遮断した通話は既定で端末の通話履歴にも通知にも残さない。
  何が止まったかはアプリ内の「記録」タブで確認する。

## ビルド

```
intl-call-blocker/
├── core/   判定ロジック（純 Kotlin・Android 非依存・テストあり）
└── app/    Android アプリ（Telecom サービス ＋ Jetpack Compose の UI）
```

- Android Studio（Ladybug 以降）でこのディレクトリを開く
- `minSdk 29` / `compileSdk 35` / AGP 8.7.3 / Kotlin 2.0.21
- 版は `gradle/libs.versions.toml` に集約

```bash
./gradlew :app:assembleDebug     # APK を作る（Android SDK が必要）
./gradlew :app:installDebug      # 実機へ入れる
```

### 判定ロジックのテスト（Android SDK 不要）

```bash
./verify-core.sh
```

44 件のテストが走る。実機もエミュレータも Android SDK も要らない。

```
CallScreeningEngineTest   26 tests
PhoneNumbersTest          12 tests
CountryCodesTest           6 tests
```

`--configure-on-demand` を付けているのが要点で、これが無いと Gradle は `:app` も
構成しに行き、Android SDK の無い環境では `:core:test` すら起動できない。
ルートの `build.gradle.kts` でプラグインを宣言していないのも同じ理由。

主なテスト内容:

- 緊急通報が**全機能 ON でも発着信ともに通る**こと
- MMI コードの発信を横取りしないこと
- 桁数の違う事業者選択番号（`001` / `0033` / `0061` / `005345`）すべてで
  `010` を見つけられること
- 許可リストが表記の揺れ（`090-1234-5678` ⇔ `+819012345678` ⇔ 全角）を吸収すること
- 桁を含まない許可ルール（`*` など）が**全許可の事故にならない**こと
- 国番号表が接頭辞符号として壊れていないこと（手打ちの表なので機械検査する）

### 実機で確認すること

ロジックはテストで担保できるが、次の 3 点はテストでは担保できないので実機で見る。

1. 役割の取得ダイアログが両方（screening / redirection）出て、許可後に
   トップ画面の表示が「取得済」へ変わるか
2. 国際着信が**呼び出し音を鳴らさずに**切れるか
3. `110` への発信が止まらないか（**必ず確認すること**）

## ライセンス / 注意

個人利用を前提とした実装。Google Play へ公開する場合、
`ROLE_CALL_SCREENING` / `ROLE_CALL_REDIRECTION` を使うアプリは
Play Console でのポリシー申告が必要になる点に注意する。
