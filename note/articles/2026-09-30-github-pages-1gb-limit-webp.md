ブラウザゲームを37本<!--fact:games-->作っていたら、ある日リポジトリが1.6GBになりました。

**GitHub Pagesの公開サイトには1GBの上限があります。** 超えると詰みます。
画像を全部PNGで置いていたのが原因でした。

WebPへ再エンコードすれば解決すること自体は分かっていました。
実際、戦国シミュレーション1本だけでも660MB→89MB（7.4倍）まで縮み、
リポジトリ全体では1.6GB→264MB（assetsは1.5GB→209MB）まで落ちました。

この記事の中身は「WebPにしたら軽くなった」ではありません。
**数百枚の画像パスを一括で書き換えるスクリプトを書くと、
「どこも間違っていないのに、特定の組み合わせのときだけ壊れる」バグが何種類も出る**
という話です。切り出し矩形（source-rect）がずれて絵が消える話は、
すでに別の記事で1回分の事例として書いたので、ここでは触れません。
今回書くのは**パスの書き換えそのものが持っている罠**です。

## 全部を変換してはいけない

最初につまずいたのは「対象を全部WebPにする」という前提そのものでした。
実際には**変換してはいけない画像が最初から4種類あります。**

- `assets/marketing/ig-*.jpg` — Instagram Graph API はJPEGしか受け付けない。変換すると投稿が通らなくなる
- `assets/og/*` — OGP画像。SNS側のWebP対応が不安定
- `assets/maps/strategic-japan.png` — 検証スクリプトがこのパスを文字列で直書きして参照している
- `assets/sengoku/gpt/*.jpg` — 肖像・地形のアトラス画像。合計1.9MBしかなく、
  縮めて浮く容量よりも「source-rectの直書き箇所に触るリスク」のほうが割に合わない

最後の1つが個人的には一番刺さりました。**「軽くなるから変換する」は常に正しいわけではなく、
浮く容量とリスクを天秤にかけて「触らない」を選ぶべき場所がある**ということです。
この判断を毎回人間が覚えておくのは無理なので、いまはこの4つを
`verify-asset-format.mjs` の除外リストにコードとして持たせています。
リストに載せるときは必ず理由を書く決まりです。理由の書けない例外を増やすと、
検査そのものが「なんとなく除外」の温床になって意味を失うからです。

## 一括置換は「見えている参照」しか直せない

`optimize-assets.py` は、変換した画像の**フルパス文字列**をコード中から検索して置換します。
*assets/foo/bar.png* を *assets/foo/bar.webp* に、という単純な文字列置換です。

これで直る参照と、直らない参照があります。直らないのは、
**実行時に文字列を組み立ててからパスにしている箇所**です。

```js
// こういう書き方はコード中に "assets/foo/bar.png" という文字列が
// 1箇所も存在しないので、フルパス一致の置換では絶対に見つからない
const path = ASSET_ROOT + type + '.png';
```

スクリプトはこれを検出するための正規表現（`\+\s*['"]\.(?:png|jpe?g)['"]` や
`` \$\{[^}]*\}[^'"`]*\.(?:png|jpe?g) ``）を持っていて、
該当行があれば警告だけして処理は続けます。**直すのは人間の役目**です。
警告を無視すると、画像は変換されたのに参照は旧ファイルを指したままになり、
消えたファイルへの読み込みが404を出します。

## パスを分割して書いている箇所は、さらに厄介

もう1つ別の書き方があります。`ASSET_ROOT + 'gpt/foo.png'` のように、
**定数と部分パスを連結している**書き方です。こちらは文字列としては存在するので、
フルパス一致だと引っかからず、旧拡張子の断片だけがコード中に残ります。

これを拾うための専用スクリプトが `fix-webp-refs.py` です。
考え方は「後方一致」——*assets/a/b/c.png* というパスに対して、
*a/b/c.png* でも *b/c.png* でも *c.png* でも、後ろから一致すれば置換候補にする、
というものです。ただしこれをそのままやると**2つの事故が起きます。**

**事故1: ディレクトリを跨いで衝突する。**
*assets/A/icons/x.webp* が変換済みでも、まだ変換していない
*assets/B/icons/x.png* を参照している箇所まで *icons/x.png* の後方一致で拾ってしまい、
存在しないパスへ書き換えてしまいます。実際にこれで2026-08-02に13件の参照を壊しました。

**事故2: 裸のファイル名だけの一致が別ゲームに当たる。**
`hero.jpg` を置換対象にしたら、**別ゲームの `misato-hero.jpg` の一部にまで一致**して、
そちらの参照まで書き換えてしまいました。ファイル名は文字列としては部分一致するので、
プログラムには「間違っている」ことが分かりません。

対策は2つとも「**まだ残っている本物の候補と衝突しうる置換は、そもそも実行しない**」でした。

```python
# 後方一致はディレクトリを跨いで衝突する。
# 「その後方一致が、まだ残っている旧ファイルにも当たりうるか」を先に調べ、
# 曖昧な後方一致は使わない
ambiguous = set()
for r in remaining:  # まだ変換していない旧ファイルたち
    parts = r.split(os.sep)
    for i in range(len(parts)):
        ambiguous.add(os.sep.join(parts[i:]))
```

そしてファイル名の部分一致そのものを封じるために、
**直前の1文字がパスを構成する文字でないことを正規表現の否定先読みで要求**しています。

```python
# 素の部分文字列一致は誤爆する。`hero.jpg` が `misato-hero.jpg` の一部に当たって
# 別ゲームの参照を壊した（2026-08-02）。直前がパス構成文字でないことを必ず要求する。
big = re.compile(r"(?<![A-Za-z0-9_\-.])(" + "|".join(re.escape(k) for k in keys) + r")")
```

`hero.jpg` の直前に `-` があると、この否定先読みで弾かれます。
**「文字列として含まれているか」ではなく「パスの区切りとして含まれているか」を見る**、
というのがここでの教訓です。

## もう1つ地味に効いた罠: アルファ

これは書き換えではなく変換そのものの罠です。**RGBAの画像をRGBとして保存すると、
透明だった部分が白い箱になります。** `optimize-assets.py` は変換前にモードを見て、
透過情報を持つ画像だけ `RGBA` を維持するようにしています。

```python
if im.mode not in ("RGB", "RGBA"):
    im = im.convert("RGBA" if (im.mode == "P" and "transparency" in im.info)
                     or "A" in im.getbands() else "RGB")
```

これも例外は出ません。画像は正しく読み込まれ、正しく描画されます。
**背景だけが、本来透明だったはずの場所に白く出ます。**

## 方針は書くだけでは守られない

ここまでの対策を全部入れて、1.6GBのリポジトリは264MBまで縮みました。
CLAUDE.mdにも「アセットは原則WebP」と明記しました。

**それでも3週間後、PNGが235枚・384MB戻っていて、assetsは587MBまで膨らんでいました。**

原因は単純です。方針は文書に書いてあるだけで、**守られているかを確かめる手段が
どこにも無かった**からです。新しい画像を追加するとき、WebPに変換するかどうかは
毎回人間の判断に委ねられていて、忙しいときはPNGのまま置かれました。
方針を書いた側も気づかないまま増え続けました。

これを2026-08-25に再変換した後、`verify-asset-format.mjs` という検査を追加して、
方針を文書ではなく機械で守る形に変えました。作るときに気をつけたのは次の2点です。

**1. 新規アセットは `git add` する前は未追跡ファイルであること。**
`git diff` だけを見ていると、これから追加されようとしている画像を素通りします。
なので検査は `git diff HEAD --diff-filter=AM` と
`git ls-files --others --exclude-standard`（未追跡ファイル一覧）の両方を見ます。

**2. 小さい画像まで指摘すると、検査そのものが無視されるようになる。**
数KBのアイコンをPNGのまま置いても実利はほぼ無いのに、そこまで赤くすると
「またこの検査か」で流されるようになります。変換して実際に容量が縮む
100KB以上だけを不合格にし、それ未満は件数の参考表示に留めています。
**検査は正しさより先に、無視されないことを設計しないといけない**というのが、
ここでの一番の気づきでした。

## まとめ

- **「軽くなるから全部変換する」は間違い。触らないほうがいい場所には、
  理由をコードに書いて例外として持たせる**
- **一括置換で直せるのはフルパス一致だけ。実行時に組み立てるパスと、
  分割して書いているパスは別に検出する**
- **ファイル名の部分一致で置換しない。パスの区切りとして一致しているかを見る**
- **RGBA画像はRGBAのまま保存する。落とすと背景が白い箱になる**
- **方針は文書に書いただけでは守られない。守っているかを確かめる検査を、
  未追跡ファイルまで含めて機械的に走らせる**
- **検査は「無視されないこと」もセットで設計する。小さすぎる違反まで赤くすると、
  検査自体が形骸化する**
