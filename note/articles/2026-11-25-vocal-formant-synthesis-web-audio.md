ブラウザだけで動く歌声合成エンジンを作っていると、**例外もエラーも一切出ないのに、
作った声が「あ」「い」「う」どれを歌わせても同じに聞こえる**という症状にぶつかることがあります。

コードは最後まで実行され、音も鳴ります。ただ、母音の違いが聞き取れないのです。
原因は実装ミスではなく、**声道の物理を1行省略していた**ことでした。

歌声合成は、母音ごとに決まる共振周波数（フォルマント）をフィルタで再現する「ソース
フィルタ方式」という考え方で作れます。声帯が鳴らす音源を、母音の形をした帯域フィルタに
通すだけ、という理屈自体は単純です。ところが実際にブラウザの Web Audio API で組んでみると、
物理的な前提を1つ省いただけで母音が作り分けられなくなったり、フィルタの構成によっては
特定の音符だけ耳に痛いほど音量が跳ねたりします。どちらも例外やエラーは一切出ません。
「音は鳴っているが、何かがおかしい」という形でしか現れないため、原因の切り分けには
波形やスペクトルを数値で見る以外の方法がありません。

## この記事で分かること

- フォルマント合成で母音が作り分けられなくなる、声道の物理上の理由
- 並列フォルマント帯域フィルタを使うと、音符ごとに音量が跳ねてしまう現象と、その補正方法
- 録音した音声からメロディを拾う（YIN法によるピッチ追跡）ときに踏みやすい落とし穴
- 「音が途切れて同じ音符が2つに割れる」現象の見分け方

## 先に結論

- **声帯波のスペクトル傾斜に、唇からの放射特性（+6dB/oct）を必ず乗せる。** 声帯波だけ
  （-12dB/oct相当）を再現すると高次のフォルマントが沈み、母音の区別が聞き取れなくなる
- **並列フォルマント帯域フィルタは、基音が共振周波数に重なった音符だけ音量が跳ねる。**
  帯域フィルタのQを帯域幅で頭打ちにし、鳴らす前に実効音量を見積もって正規化する
- **YIN法でのメロディ採譜は、音量の谷の深さと、谷のあとも音が鳴り続けているかの両方を
  見て「同じ音符」か「歌い直し」かを判定する。** 子音のアタックの有無では見分けられない
- **録音した音声の帯域は、主旋律と伴奏で絞り方を変える。** 広い帯域で追うと伴奏のベース音を
  拾ってしまう

## 1. 声帯波だけでは、どの母音も同じに聞こえる

ブラウザ内で完結する歌声合成ツールのフォルマント合成エンジン（`ai-vocal-synthesizer-classic.html`）には、
母音ごとの共振周波数（フォルマント）をテーブルで持つ実装があります。

```js
// 母音のフォルマント（F1〜F4, Hz）・各帯域のゲイン・帯域幅
const VOWELS = {
  a:{f:[780,1150,2700,3400], g:[1.00,0.80,0.50,0.28], bw:[130,160,300,420]},
  i:{f:[300,2250,2950,3600], g:[1.00,0.90,0.62,0.38], bw:[110,230,330,450]},
  // ...
};
```

このテーブルだけでは、母音は作り分けられません。ソースコードのコメントには、
その理由が明記されています。

```js
// 声帯波は約 -12dB/oct、唇からの放射特性が +6dB/oct。合わせて概ね -6dB/oct になる。
// これを入れないと F2/F3 が埋もれ、どの母音も同じ「あ」に聞こえてしまう。
const SOURCE_TILT = bright => 1.35 - 0.50 * bright;
```

声帯が作る音源（声帯波）のスペクトルは、倍音が上がるほど急激に減衰します（おおよそ
-12dB/oct）。これだけをフォルマントフィルタに通すと、高い方の倍音がほとんど残らないまま
フィルタへ入るため、F2・F3（2番目・3番目のフォルマント）の出力が極端に小さくなります。
F1（1番目のフォルマント）だけが相対的に大きく残り、どの母音を指定しても同じ「あ」に
近い音になってしまう、というのが症状の正体です。

実際の声はここに、唇から放出される際の音響的な特性（放射特性、+6dB/oct）が加わります。
声帯波の-12dB/octと放射特性の+6dB/octを足すと、合計でおおよそ-6dB/octの傾斜になります。
`SOURCE_TILT` はこの合成済みの傾斜を倍音の指数として使っており、`bright`（声の明るさ）
パラメータで1.35から0.85の範囲（-6dB/oct寄りの値）を取るようにしてあります。

## 2. フォルマント帯域フィルタは、音符ごとに音量が跳ねる

母音のフォルマントは、並列に並べた4本の帯域フィルタ（bandpass）で再現されています。

```js
// 声帯波 × フォルマント帯域フィルタ4本（並列）
for (let i = 0; i < 4; i++){
  const bq = ctx.createBiquadFilter();
  bq.type = 'bandpass';
  // ...
  bq.Q.value = formantQ(target.f[i] * shift, target.bw[i] * shift);
}
```

帯域フィルタのQ（鋭さ）を中心周波数÷帯域幅で素直に計算すると、F1が鋭くなりすぎます。
そのまま使うと、**歌う音符の基音（ピッチ）がたまたまF1の周波数に重なった音符だけ**、
フィルタの共振で極端に大きく増幅されてしまいます。対策として、Qの値には上限と下限が
設けられています。

```js
const Q_MIN = 1.1, Q_MAX = 6.0;
const formantQ = (f, bw) => clamp(f / bw, Q_MIN, Q_MAX);
```

これだけでは「鋭くなりすぎない」だけで、「音符ごとの音量差」自体は残ります。
そこで、実際に音を鳴らす前に、その音符の基音とフォルマントの位置関係から**実効音量を
見積もって正規化**する関数が置かれています。

```js
/* 声帯波 × フォルマント帯域フィルタ4本 を通したときの実効音量を見積もる。
   基音がフォルマントに重なる音符だけが極端に大きくなるのを打ち消すために使う。 */
function formantLevel(f0, vow, shift, bright){
  const tilt = SOURCE_TILT(bright);
  let e = 0;
  for (let n = 1; n <= 40; n++){
    const f = n * f0;
    if (f > 16000) break;
    const amp = Math.pow(n, -tilt);
    let h = 0;
    for (let i = 0; i < 4; i++){
      const fc = vow.f[i] * shift;
      const q = formantQ(fc, vow.bw[i] * shift);
      const r = f / fc - fc / f;
      h += vow.g[i] / Math.sqrt(1 + q * q * r * r);
    }
    e += amp * amp * h * h;
  }
  return Math.sqrt(e);
}
```

倍音ごとの振幅（`n^-tilt`）と、4本のフィルタそれぞれの振幅応答（`1/√(1+Q²r²)`の形）を
掛けて二乗和を取ることで、**実際に音を鳴らす前に、その音符がどれくらいの音量になるかを
計算で求めている**ことが分かります。得られた実効音量を基準値（`LEVEL_REF`）と比較し、
その比率を音符ごとのゲインに反映すれば、基音がフォルマントに重なった音符だけ大きくなる
現象を抑えられます。

## 3. 録音した音声からメロディを拾う — YIN法と、その落とし穴

このツールには、再生中の音声やマイク入力からメロディを採譜する機能もあります。
基本周波数（ピッチ）の推定には、YIN法と呼ばれる手法が使われています。

```js
/* YIN：1フレームぶんの基本周波数を推定する（差分関数 → 累積平均正規化 → 放物線補間） */
function yinFrame(x, off, W, sr, tauMin, tauMax, thr){
  const cm = new Float32Array(tauMax + 2);
  let run = 0, best = -1;
  for (let tau = tauMin; tau <= tauMax; tau++){
    let s = 0;
    for (let i = 0; i < W; i++){ const d = x[off + i] - x[off + i + tau]; s += d * d; }
    run += s;
    cm[tau] = s * (tau - tauMin + 1) / (run || 1e-9);
  }
  // ...
}
```

音声の1フレームごとに、ずらし幅（遅延）を変えながら波形同士の差分を取り、
差分が最小になる遅延（≒周期）を基本周波数として求める、というのがYIN法の基本的な
考え方です。このツールの実装では、推定した基本周波数が前後のフレームと比べて
1オクターブ近くずれている場合に補正する処理も入っています。

```js
// オクターブ飛びの補正（YIN は倍音/低次にはまることがある）
if (recent.length >= 4){
  const ref = median(recent);
  if (Math.abs(m - ref) > 9.5){
    const up = m + 12, dn = m - 12;
    if (Math.abs(up - ref) < 4.5) m = up;
    // ...
  }
}
```

YIN法は、信号の倍音や分数調波（低い次数の候補）に飛び移ってしまうことがあるため、
直前の推定値の中央値と大きくずれた場合に、1オクターブ上下へ補正を試みる作りです。

### 同じ音高の音符を「ひと続き」とみなすか、「分かれた2音符」とみなすか

採譜処理でもう一つ厄介なのが、**同じ高さの音が続くときに、どこで音符を区切るか**です。
単純に「音量がいったん下がって、また上がったら歌い直し（新しい音符）」という判定だけでは、
雑音の多い録音でピッチ追跡が一瞬途切れて同じ高さで再取得されたときに、本来は1つの音符を
2つに割ってしまいます。

```js
// 雑音の多い録音では、持続音の途中でピッチ追跡が0.1秒ほど途切れ、同じ高さで再取得される
// （＝1つの音符が2つに割れる）。歌い直しなら音量がいったん落ちるが、追跡の取りこぼしなら
// 音は鳴り続けている。無声と判定された区間の音量で見分けて橋渡しする。
// （子音のアタックの有無で見分けようとしたが、アタックは音符の境目でほぼ必ず立つので使えない）
function gapStillSounding(prev, n, frames){
  const from = Math.max(0, Math.round(prev.t1 / (HOP_MS / 1000)));
  const to = Math.min(frames.length - 1, n.si);
  if (to <= from) return true;
  let sum = 0, cnt = 0;
  for (let k = from; k < to; k++){ sum += frames[k].rms; cnt++; }
  const gapRms = cnt ? sum / cnt : 0;
  return gapRms > Math.min(prev.peak, n.peak) * 0.6;
}
```

コードのコメントにある通り、**子音のアタック（音の立ち上がり）の有無で判定する方法は
使えません**。アタックは普通に歌い直したときの音符の境目でもほぼ必ず立つため、これを
条件にすると、本来つながっているはずの音符まで分割してしまいます。代わりに、
「音が途切れたと判定された区間でも、実際には音量がまだ鳴り続けているか」を見て
橋渡しする、という方法が採られています。

音量の谷についても、浅い谷まで歌い直しの合図として拾うと、伴奏の付いた音源では
ベース音を拾ってしまい逆効果になるため、**十分に深い谷（直前のピーク音量の0.42倍）**
に限定するコメントが残っています。

```js
// 音量の谷でも歌い直しを拾う。ただし浅い谷まで拾うと、伴奏つきの音源で
// 細切れになりベース音を拾う区間が増えて逆効果だった（実測: 14/14 → 1/14）。
// 深い谷（0.42倍）に限定し、取りこぼしはピアノロールで直せるようにしてある。
```

## 4. 音を拾う帯域は、主旋律と伴奏で絞り方を変える

伴奏の付いた曲から主旋律を拾いたいとき、広い周波数帯でYIN法を走らせると、
音量の大きいベース音を主旋律と誤認してしまうことがあります。このツールは、
まず声の帯域に絞って追跡し、うまく拾えなければ低い帯域へ切り替える、という
二段構えの設定を持っています。

```js
// 自動モードはまず主旋律の帯域(150-1200Hz)で追い、声が取れなければ低い帯域へ落とす。
const AUTO_RANGES = [{fmin:150, fmax:1200}, {fmin:80, fmax:600}];
```

また、音楽配信サービスの再生音声はDRMで保護されていることが多く、ブラウザの
「タブの音声を取り込む」機能では無音になります。この場合に備えて、取り込んだ音声が
無音だったときの案内文も用意されています。

```js
log('音が入っていません。音楽配信サービス（LINE MUSIC・Spotify など）の音声はDRMで保護されており、' +
    'タブ音声の取り込みでは無音になります。スピーカーで再生して「🎤 マイク」で録音してください / ...
```

## まとめ

- **声帯波のスペクトル傾斜に、唇の放射特性（+6dB/oct）を乗せ忘れると、合成した声は
  高次のフォルマントが沈み、母音の区別が聞き取れなくなる。** 声帯波単独の-12dB/octと
  放射特性の+6dB/octを足した、概ね-6dB/octの傾斜が必要
- **並列フォルマント帯域フィルタは、Qを帯域幅で頭打ちにするだけでは音量差を消せない。**
  音を鳴らす前に、基音とフォルマントの重なりから実効音量を計算し、音符ごとに正規化する
- **YIN法によるピッチ追跡は、オクターブ飛びの補正と、同一音高の音符をつなぐかどうかの
  判定が要る。** 判定には「音量の谷の深さ」と「谷の間も音が鳴り続けているか」を使う。
  子音のアタックの有無では区別できない
- **録音の帯域は、主旋律と伴奏つきの音源で絞り方を変える。** 広い帯域だとベース音を拾う
