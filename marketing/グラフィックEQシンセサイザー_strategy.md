## 0. 訴求できる事実（実装で確認済み）

コンテンツを書く際は、この表の範囲を超えないこと。

| 項目 | 実装の内容 |
|------|-----------|
| EQ | 10バンド（31.25 / 62.5 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz）、±18 dB、両端シェルビング・中央ピーキング（Q=1.41） |

| シンセ | 減算合成。OSC2基＋サブ＋ノイズ、フィルター＋フィルターEG、ADSR、ポリ／モノ＋グライド、アルペジエーター（ホールド可） |

| 可視化 | 対数周波数軸スペクトラム＋EQカーブ重ね描き（`getFrequencyResponse` の実測値）、ピークホールド線、波形モニター、カーソルで周波数・dB読み取り |
| 入力 | 画面鍵盤2オクターブ（C3から）、PCキーボード（A〜; ／ Z X でオクターブ）、Web MIDI（Chrome / Edge） |
| 出力 | EQ通過後を16bitステレオWAVで書き出し |
| 共有 | 音色・EQ・シーケンスをURLハッシュに埋め込む共有リンク（サーバー保存なし） |
| 実装 | フレームワーク不使用・Web Audio APIのみ・APIキー不要・外部送信ゼロ |

## 1. 競合マーケティング調査

### カテゴリA: オンラインEQツール
RemoveVocals / SnipSound / Binauro / AudioTrick / Hearably / SoundTools など。

- 訴求軸はほぼ共通で **「10-band」「32Hz〜16kHz」「no upload」「no signup」「free」「your audio never leaves your device」**
- 多くが ±12 dB。ジャンル別プリセットを持つ点も共通
- ワークフローは **ファイルを入れる → EQ → 書き出す** の一方通行。音を「作る」機能はない
- SEOで「audio equalizer online」を取りに行くタイプのツールサイトが上位を占める

→ 示唆: **プライバシー訴求（外部送信ゼロ）は差別化にならない。業界の当たり前**。前面に置くのではなく、信頼の裏付けとして添える位置に落とす。

### カテゴリB: ブラウザシンセ
Zupiter（モジュラー）、Web Synth（ameo.dev）、WebSynths、Tone Generator、SoundTools Granular など。

- 訴求軸は「モジュラー」「no install」「Web MIDI 対応」「オフラインで動く」
- 技術系の話題化はモジュラー／WASM／DSP実装など **実装の深さ** で起きている（例: Rust + WebAssembly + SIMD による FM 合成の記事）
- 一方で、**ミキシング品質のEQと可視化を持つブラウザシンセはほとんど無い**。EQは付いていてもフィルター扱いで、周波数特性を実測表示するものは少数

### カテゴリC: 日本語圏（Qiita / Zenn）
「Web Audio API でシンセを作った」系の記事は継続的に読まれている定番テーマ。ubsecure のブログ連載や Qiita のシリーズ記事など、**チュートリアル寄りの実装解説が長期的に流入を得る**傾向。

- 示唆: 単発の「作りました」告知より、**ハマりどころを書いた実装記事**の方が寿命が長い。本ツールには「Web Audio は例外を出さずに無音になる」という強いフックがある

### 拡散パターンの所見
- X の技術系は **画面の動きが見えること** が前提。EQカーブとスペクトラムが動く短い画面録画が最も効く
- Reddit（r/webaudio 等）は自己宣伝に厳しいサブが多い。**「作った物の宣伝」ではなく「実装上の知見の共有」として投稿**し、リンクは本文中に自然に置く
- 日本語圏の反応は平日夜（21:00〜23:00 JST）、英語圏は米東部の平日午前（＝23:00〜翌1:00 JST）に寄せる

## 2. ターゲットペルソナ

### P1: 個人開発者・Webフロントエンド（主ターゲット）
- 25〜40歳、日本＋英語圏。X と Zenn / Qiita / Hacker News を巡回
- Web Audio API に興味はあるが「サンプルを動かして終わった」段階
- 刺さる点: **フレームワーク不使用・1ファイル・実装が読める**／`getFrequencyResponse` の実測描画／45項目の自動検査
- 行動: ソースを読む → Star → 引用ポスト

### P2: DTM初学者・音楽学習者（拡散の担い手）

- 刺さる点: **EQを動かすとカーブとスペクトラムが同時に動く＝耳と目が繋がる**。プリセット10種で違いを聴き比べられる
- 行動: 触って面白がって共有リンクを貼る

- ポッドキャスト収録・配信・動画編集の前処理をしたい層
- 刺さる点: 音声ファイルとマイクを直接EQに通せる／EQ後をWAV保存できる／アップロード不要
- 行動: ブックマークして再訪

## 3. USP（差別化ポイント）

1. **「音を作る」と「音を整える」が同じ画面にある**。オンラインEQはファイル処理専用、ブラウザシンセはEQを持たない。シンセ／音声ファイル／マイクの3系統すべてが同じ10バンドEQを通るのは、調べた範囲では例が少ない
2. **EQカーブがスペクトラムに重なる**。設定値のイラストではなく `getFrequencyResponse` の実測を描いている。「上げたつもり」と「実際にかかっている量」がズレない
3. **信号経路でハウリングを解いている**。アナライザを出力ゲインより前段に置いたので、スピーカー出力を切ってもスペクトラムと録音が生きる。マイク利用時の実用上の壁を、注意書きではなく設計で回避
4. **無音にならないことを機械で確かめている**。Web Audio は未接続やエンベロープの時刻ミスで例外を出さずに無音になる。Playwright 45項目でアナライザのピーク値・声部リーク・EQの実効まで検証している
5. **フレームワークゼロ・ビルドゼロ・APIキー不要・外部送信ゼロ**。1ファイルのHTMLで、読めば全部わかる

**ポジショニング一文**:
> オンラインEQは音を整えるだけ、ブラウザシンセは音を作るだけ。これは作った音をその場で整えて、効きを目で見て、書き出せる1ページ。

## 7. リスクと注意

- **マイク＋スピーカーのハウリング**: 触った人が不快な体験をすると悪印象が拡散する。ポストで「マイクを使うときはヘッドホンで」と一言添える。実装にも警告があるが、SNS上でも先に言う
- **Web MIDI の非対応ブラウザ**: Safari / Firefox では使えない。「MIDI対応（Chrome / Edge）」と必ず但し書きを付ける
- **モバイルでの体験**: 情報密度が高いUIのため、スマホ流入が多いポストでは離脱しやすい。「PCで開くのがおすすめ」を添えるか、PC比率の高い時間帯に投稿する
- **誇張の回避**: 「プロ品質」「DAW不要」等は使わない。書けるのは実装にある機能まで
