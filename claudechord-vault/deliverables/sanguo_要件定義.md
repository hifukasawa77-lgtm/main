# 要件定義書 — 三国志・天下三分 機能拡張

> プロジェクトハブ: [[sanguo]] ／ 下流: [[sanguo_基本設計]] → [[sanguo_詳細設計]]

## 1. 背景・目的

### 1.1 現状

`sanguo.html`（326行・単一HTML・Canvas APIのみ・フレームワーク不使用）は、20都市の戦略マップ、
11x8ヘックスの合戦、6勢力の外交、150人超の武将名鑑を既に備える。しかし遊びの循環が痩せている。

| 領域 | 現状 | 問題 |
|---|---|---|
| シナリオ | 8件のイラスト＋口上のみ。`startScenario()` は `state.year` とログしか差し替えない | **赤壁(208年)を選んでも董卓が長安を保持した190年配置で始まる。8枚の専用イラストが実質的に死んでいる** |
| 内政 | `develop()` 1種のみ（100金 → prosperity +8〜12） | 選択肢がなく、金が余ったら押すだけのボタン |
| 登用 | `recruit()` が `GENERAL_IDS` の未使用先頭を機械的に付与 | プレイヤーは誰が来るか選べず、武将に愛着が湧かない |
| 武将 | 都市に貼り付き。移動・忠誠・引き抜きなし | 150人超の武将データが名鑑の飾りに留まる |
| 知力 | 内政ボーナスと「弓兵になるか」の分岐にしか使われない | 三国志の中核である知略が体験に存在しない |
| 戦闘 | 兵力と兵種三すくみのみ。`bCleanup()` は「兵力が初期の12%未満で一律壊走」 | 士気・地形活用・演出の起伏がなく、数の暴力が唯一の最適解 |
| 経済 | 金のみ。`endTurn()` で毎ターン garrison +2 が無条件 | **「兵を貯めて殴る」が支配的戦略。維持コストがないため軍拡に歯止めがない** |

### 1.2 目的

1. **史実の時代を選ぶ体験を成立させる**（8シナリオを実データ化し、既存イラスト資産を機能させる）
2. **「兵を貯めて殴るだけ」の支配的戦略を崩す**（兵糧という維持コストと遠征コストでジレンマを作る）
3. **知力・統率を意味のあるステータスにする**（計略・内政分化・忠誠・士気の判定軸に組み込む）
4. **見せ場を作る**（名乗りを上げての一騎打ち＝深澤が特に指名した演出。三国志演義の華）

### 1.3 スコープ外（今回やらないこと）

- 3D化・アニメーション動画・外部音源の導入
- マルチプレイ・サーバ連携・外部API利用
- 都市数の増加（20都市を維持。地図画像と座標が既存資産のため）
- 武将の顔グラフィック新規生成（既存アトラスを流用。有料API禁止規約に抵触するため）

## 3. 非機能要件

### 3.1 パフォーマンス

| 項目 | 基準 |
|---|---|
| マップ描画 | `draw()` の1回あたり 16ms 以内（都市20・パーティクルなし） |
| 合戦描画 | `bDraw()` 60fps 維持。ヘックス88枚＋スタック最大8＋fx |
| 一騎打ち演出 | 全体で6〜10秒以内。スキップ可能であること |
| ターン処理 | `endTurn()`（内政AI・兵糧計算・計略AI含む）が 120ms 以内 |
| 総ページ重量 | 追加後も HTML＋参照ローカルJS の合計で 400KB 以内（画像除く） |

### 3.2 ブラウザ・環境対応

- Chromium / Firefox / Safari の最新版
- `file://` 直開きで動作すること（`dynamic-test` が file:// で検証するため。`fetch()` と ES Modules は使用禁止）
- GitHub Pages（静的ホスティング・ビルドなし）で動作すること
- モバイル: 横向き必須ゲート（既存 `.sanguo-landscape-gate`）を維持。**1260x540 相当のビューポートで追加UIが破綻しないこと**

### 3.3 保守性

- `sanguo.html` の単一巨大化を避けるため、データ表は外部 JS に分離する（3.5 参照）
- 追加関数は既存の命名規約に従う（マップ系は接頭辞なし、合戦系は `b` 接頭辞）
- マジックナンバーは定数テーブル（`ECON` / `DUEL` / `PLOT` / `WEATHER`）に集約する

### 3.4 セーブ互換性

- 既存 `sanguo_save_v1` を持つプレイヤーのセーブを**壊さない**
- `sanguo_save_v2` を新設し、v1 検出時は既定値を補ってマイグレーションする
- マイグレーション後、v1 キーは削除する（二重管理を避ける）
- セーブ破損時は例外を握りつぶしてタイトルへ戻す（既存 `loadGame()` の try/catch 方針を踏襲）

### 3.5 制約（CLAUDE.md 準拠）

| 制約 | 内容 |
|---|---|
| フレームワーク | 不使用。素の HTML / CSS / JavaScript ＋ Canvas API のみ |
| ビルドツール | 不使用 |
| ライブラリ | CDN 経由のみ許可。**本件では新規追加しない** |
| APIキー | 有料APIキーの設定・記述を全面禁止。画像はプロシージャル生成か既存アセット流用 |
| デザイン | 黒背景＋金(`#e4c27b`)の既存三国志テーマを厳守。**サイバーパンク的演出（ネオングロウ過多・マゼンタ等の原色ネオン・SF都市風）は禁止** |
| 表記 | UI は日英バイリンガル |
| Git | 作業ブランチ `claude/sangokushi-feature-proposals-j5ab1l`。**main へ直接 push しない** |

## 4. 制約・前提

### 4.1 既存資産の前提

- `CITIES` の `x / y / neighbors` は地図画像に紐づく**不変の地理情報**。シナリオで上書きしない
- `GENERAL_JP` / `GENERAL_IDS` は並行配列でインデックス対応。`EXPANDED_PORTRAIT_ATLASES` で150人超に拡張済み
- `GENERAL_STATS` 未定義の武将は `statFor()` が ID 文字列ハッシュから決定論的に生成する。**この決定論性は在野プールの再現性に依存するため壊さない**
- 8枚のシナリオイラストは `assets/sanguo/gpt/scenarios/` に存在済み（新規生成不要）
- 合戦背景12枚と武将アトラスも既存。**新規画像生成は不要**
- `sfx()` は Web Audio API のプロシージャル生成。外部音源ファイルなし

### 4.2 史実表現の前提

- 20都市という粒度では史実の郡県を完全再現できない。**代替マッピングを明示的に許容する**
  - 例: 呂布の本拠「下邳」は都市リストに存在しないため `he_fei`（淮南・徐州南部）で代替する
- 勢力の乱立を避けるため、**`han`（漢室）を「未統合の漢朝勢力（朝廷・宗室系太守・張魯等）を束ねる中立枠」として運用する**
- 追加勢力は4つ（`turban` / `lubu` / `biao` / `nanman`）に留める。勢力カード UI と外交画面の破綻を避けるため

### 4.3 バランス設計の前提

- 現在の勝利条件「自領が全都市の60%以上」はシナリオによって成立直後に達成されうる（例: 208赤壁の魏は開始時10/20=50%）。**シナリオごとに閾値をパラメータ化する**
- 兵糧は「大軍を維持すると飢える」ジレンマを作ることが目的。**軍拡が常に得にならない収支テーブル**を設計すること

## 6. 優先順位と分割方針

実装は **8フェーズ**に分割する（詳細は [[sanguo_詳細設計]] 第7章「実装順序表」）。
`sanguo.html` は単一ファイルで既に大きく、code-generator のタイムアウトを避けるため
1フェーズ＝1エージェントセッションを原則とする。

| 優先 | フェーズ | 内容 |
|---|---|---|
| 1 | P0 | 基盤（state拡張・都市フィールド・セーブv2・天候・定数テーブル・外部データファイル新設） |
| 2 | P1 | 機能1 シナリオ実データ化（★最優先・単体で価値が出る） |
| 3 | P2 | 機能3 内政分化＋兵糧 |
| 4 | P3 | 機能2 武将運用（配置転換・在野探索・忠誠） |
| 5 | P4 | 機能5-a 士気＋天候の戦闘反映 |
| 6 | P5 | 機能5-b 一騎打ち（名乗り演出） |
| 7 | P6 | 機能4-a 合戦計略（火計・伏兵・混乱・鼓舞） |
| 8 | P7 | 機能4-b 戦略計略＋AI強化＋バランス調整 |

**P1 完了時点で単体リリース可能**とする（既存イラスト8枚が機能する時点で価値が確定するため）。
