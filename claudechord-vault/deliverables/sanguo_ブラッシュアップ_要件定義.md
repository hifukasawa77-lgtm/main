# 要件定義書 — 三国志・天下三分 ブラッシュアップ（第2次拡張）

> プロジェクトハブ: [[sanguo]] ／ 下流: [[sanguo_ブラッシュアップ_基本設計]] → [[sanguo_ブラッシュアップ_詳細設計]]
> 前次: [[sanguo_要件定義]]（P0〜P7・実装済み）

## 1. 背景・目的

### 1.1 現状（2026-08-03 実測）

第1次拡張（P0〜P7）で `sanguo.html` は 2,693行・8シナリオ・10勢力・約194名の武将・
士気/天候/一騎打ち/計略まで備えた。Playwright での起動〜60ターン自動進行で
**JSランタイムエラー0件・404アセット0件**。基盤の品質は高い。

一方、実測で以下の欠落が確認された。

| # | 領域 | 実測した事実 | 問題 |
|---|---|---|---|
| 1 | 兵の再配置 | `cityPanel()` のコマンドは内政5種・人事・出陣のみ。自領間で兵を動かす手段が存在しない | **占領した都市を増強できない**。前線の兵は当該都市で `levy`（120金＋兵糧60）するしかなく、後方都市の兵は死蔵される。「戦線を作る」という戦略SLGの中核判断が発生しない |
| 2 | 行動の制約 | 1ターンの行動回数に上限がなく、`doPolicy()` は金がある限り何度でも実行できる | 金が唯一の制約。しかも 190年・魏・普通・完全放置で **金は T2:538 → T27:2,163 → T57:4,113 と単調増加**。内政上限（各100）に達すると金の使い道が消え、リソース管理が成立しない |
| 3 | AIの収束性 | 50ターン自動進行のログで、洛陽が董卓→袁紹→董卓、武昌が呉→荊州→呉、襄陽が荊州→袁紹→呉…と**同じ都市が延々と往復**する。どの勢力も統一に近づかない | 勢力図が「歴史」ではなく「ノイズ」。追うべき仮想敵が生まれない。かつ**完全放置でも57ターン滅亡しない**ため緊張感がない |
| 4 | 肖像アセット | `EXPANDED_PORTRAIT_ATLASES`（6枚・194スロット）を参照するのは `buildRoster()` ただ1箇所 | 高品質な肖像194枚が**「武将名鑑」モーダル内でしか見られない**。とくに「名乗りを上げての一騎打ち」（第1次拡張で深澤が指名した見せ場）が `bDuelDraw()` で名前・二つ名・武力の**文字だけ**で演出されている |

### 1.2 目的

1. **占領地を保持・増強できるようにする**（増援＝自領間の兵の再配置）
2. **金以外の制約を導入し、毎ターンの選択に痛みを持たせる**（政務ポイント＋兵糧買付という金のシンク）
3. **AIの勢力図を収束させ、放置すれば負ける世界にする**（進軍後の空白化バグの是正・目標の持続・増援行動）
4. **既にある肖像194枚を体験の中心に出す**（新規アセット制作ゼロで見栄えを最大化）

### 1.3 スコープ外（今回やらないこと）

- 城郭グラフィック（`assets/sanguo/gpt/castles/` 6枚）の攻城戦への組み込み → 次次期
- マップ上の勢力領域の塗り分け・シナリオ/勢力カードへの絵の追加 → 次次期
- BGM の追加、武将名鑑の検索・ソート、外交好感度の可視化 → 次次期
- `index.html` の紹介文更新（「6勢力」→10勢力）・案内エージェント `GAMES` への登録 → 本件とは別タスク
- 新規画像・音楽アセットの制作（**Graphic-Designer / Music-Generator への発注は不要**）

## 2. 要求仕様（MoSCoW）

### Must（必須・16項目）

#### 機能1 増援（自領間の兵の再配置）
- **M-01** 自軍領の都市パネルに「増援 / REINFORCE」セクションを設け、**隣接する自軍領**へ兵を送れること
- **M-02** 送る兵数は段階選択（20 / 50 / 100）。出発都市の残兵が下限を割る選択肢は選べないこと
- **M-03** 出発都市には常に最低兵（`REINFORCE.minKeep`）が残ること。空城を作れないこと
- **M-04** 到着都市の兵は上限（`levy` と同じ 150）を超えないこと。超過分は送られず、その旨をログに出すこと
- **M-05** 1都市あたり1巡1回に制限すること（武将の配置転換 `movedTurn` と同じ方式）
- **M-06** 金と兵糧のコストを要すること。不足時はボタンを `disabled` にし、理由を日英併記で `title` に出すこと（E-05 の既存規約に従う）

#### 機能2 政務ポイント（AP）
- **M-07** 勢力は毎巡「政務ポイント」を持ち、コマンドの実行がこれを消費すること
- **M-08** 上限は領地数と君主の統率から算出し、下限3・上限8にクランプすること
- **M-09** 消費表は内政・人事・軍事・外交・計略の全コマンドを網羅すること。**恩賞のみ0**（金だけの行為）
- **M-10** 残ポイントを画面上部の常設HUDに `政務 n/m` として表示すること
- **M-11** ポイント不足のコマンドは `disabled` になり、理由が日英併記で示されること
- **M-12** 毎巡の開始時に満タンへ回復すること。繰り越しはしないこと

#### 機能3 AIの収束性
- **M-13** `aiMarch()` の**出撃元が武将ゼロになる不具合**を是正すること（現状 `to.generals=from.generals.slice(); from.generals=[]`）
- **M-14** AIが自領間で兵を再配置できること（機能1のAI版）。脆弱な国境都市が補強されること
- **M-15** AIが攻撃目標を複数巡にわたり保持し、毎巡別の隣接都市へ浮気しないこと

#### 機能4 肖像の展開
- **M-16** 一騎打ちの名乗り演出に、両者の肖像が表示されること

### Should（推奨・7項目）

- **S-01** 都市パネルの武将行・在野行に肖像サムネイルを表示する
- **S-02** 勢力選択カード・外交カードに君主の肖像を表示する
- **S-03** 合戦盤上の部隊チップに武将の肖像を（円形クリップで）表示する
- **S-04** 「兵糧買付 / BUY GRAIN」を追加し、金を兵糧へ換える恒久的なシンクを設ける（相場は季節で変動）
- **S-05** AIの進軍回数を勢力の `aggression` に応じて1巡最大2回まで許し、強勢力が伸びるようにする
- **S-06** 増援の到着に伴い、送り先都市の民忠がわずかに下がる（駐屯負担）
- **S-07** `scripts/verify-sanguo-boot.mjs` を新設し、起動〜シナリオ選択〜マップ〜ターン終了〜合戦を機械検査する

### Could（任意・3項目）

- **C-01** 増援を「1巡かけて到着」にし、輸送中の部隊をマップ上に描く
- **C-02** 政務ポイントの上限に君主の特性（AI_TRAITS の development）を反映する
- **C-03** AIの勢力図推移を確認するためのデバッグ用サマリーを `state` に積む

### Won't（今回やらない）

- 兵糧の自領間輸送（**プレイヤーの兵糧 `state.food` は国庫一括のため意味を持たない**。都市別 `c.food` は AI 専用フィールド）
- 行動順・イニシアチブなど、ターン構造そのものの変更

## 3. 非機能要件

| 項目 | 要件 |
|---|---|
| 技術制約 | フレームワーク不使用。素の HTML / CSS / JavaScript（Canvas API）。ビルドツール不使用（CLAUDE.md 準拠） |
| ファイル構成 | `sanguo.html` の単一ファイル構造を維持する。外部データは既存の `assets/js/sanguo-scenarios.js` / `sanguo-lore.js` に限り、**新規ファイルは追加しない** |
| 新規アセット | **ゼロ**。肖像は既存の `sanguo-generals-atlas-01〜06.webp` を使う |
| セーブ互換 | 既存の v2 セーブから継続できること。欠落フィールドは既定値で補う（E-15 の既存規約） |
| 描画性能 | 肖像の Canvas 描画は `Image` をキャッシュし、毎フレーム生成しないこと（`bgCache` と同じパターン） |
| フォールバック | **肖像が未ロード／該当なしの場合は現行の描画に必ず落ちること**。画像待ちで盤面が消えないこと |
| 表記 | UIは日英バイリンガル。実行不可の理由は `title` に日英併記（既存 E-05 準拠） |
| デザイン | 黒背景＋シアン/パープル/金系アクセント。サイバーパンク的演出は禁止（CLAUDE.md 準拠） |
| 例外耐性 | 60ターン自動進行で `pageerror` 0件・404 0件を維持すること |

## 4. 受入基準

### 機能1 増援
1. 自軍領を選ぶと「増援 / REINFORCE」セクションが出て、隣接自軍領が送り先として並ぶ
2. 隣接自軍領がない都市では、その旨が日英併記で示され、ボタンが押せない
3. 兵100を送ると、出発都市が−100・到着都市が+100 になる（上限150で頭打ち・超過分は送られない）
4. 出発都市の残兵が `minKeep` を割る選択肢は `disabled` になっている
5. 同じ都市から同一巡に2度目の増援はできない
6. 金または兵糧が不足していると `disabled` になり、理由が `title` に出る

### 機能2 政務ポイント
7. 画面上部に `政務 n/m` が常設表示され、コマンド実行のたびに減る
8. 190年・魏（2都市・曹操 統96）で開始したとき、上限が **5** になる
9. 残0のとき、内政・出陣・登用・増援・計略・外交の全ボタンが `disabled` になり、理由が日英併記で出る
10. 恩賞だけは残0でも実行できる（金のみを消費する）
11. 「次のターン」を押すと満タンに戻る。繰り越しは起きない
12. 兵糧買付（S-04 採用時）が金を減らし兵糧を増やす。相場が春夏と秋冬で異なる

### 機能3 AIの収束性
13. AIが都市を奪ったとき、**出撃元の都市に武将が1名以上残っている**
14. 50ターン自動進行（190年・普通・完全放置）で、**最大勢力の領地が8都市以上**に達する
15. 同上の50ターンで、**同一都市の所有者交代が20ターンあたり3回以下**に収まる
16. 同上の条件（完全放置）で、**25ターン以内にプレイヤーが滅亡する**
17. AIが脆弱な国境都市へ増援を送るログが出る

### 機能4 肖像
18. 一騎打ちの名乗り（`hail`〜`name` フェーズ）で両者の肖像が表示される
19. 肖像が未ロードでも名乗り演出が破綻せず、文字だけで成立する
20. 肖像を持たない武将（アトラス範囲外）でも例外が出ない

### 全体
21. 既存の v2 セーブから「続きから」で再開でき、政務ポイントが既定値で補われる
22. 60ターン自動進行で `pageerror` 0件・404 0件
23. `node scripts/verify-sanguo-boot.mjs` が PASS する（S-07 採用時）
24. 既存の8シナリオ・10勢力・一騎打ち・計略・外交が退行していない

## 5. 想定リスク

| リスク | 影響 | 緩和策 |
|---|---|---|
| 政務ポイントが全コマンドの入口に触るため、既存の実行可否判定（`why` 文字列）と二重管理になる | 片方だけ直してボタンが押せる/押せない不整合 | **単一のゲート関数 `apGate(kind)` を新設し、全コマンドが必ず通る**。`why` の生成もそこへ集約する |
| AIの churn 修正がバランスを大きく動かし、逆にプレイヤーが即死する | 遊べなくなる | 受入基準14〜16を**数値で機械計測**し、`scripts/verify-sanguo-boot.mjs` の一部として自動化する。難易度3段の `DIFFICULTY` つまみで最終調整する |
| Canvas への肖像描画がフレーム落ちを招く | 合戦がカクつく | `Image` をモジュールスコープでキャッシュし、`drawImage` のみ毎フレーム。未ロード時は即フォールバック |
| 増援でプレイヤーが前線を無限に厚くでき、攻城が作業になる | 難易度低下 | 増援は1都市1巡1回・金と兵糧のコスト・上限150で頭打ち。かつ政務ポイントを1消費する |
| 単一HTMLの行数がさらに増える（現在2,693行） | 可読性・コンテキスト消費 | 機能ごとに区切りコメントを入れ、定数は既存の `ECON` / `PERSONNEL` と同じ位置にまとめる |

## 6. 実装フェーズと単体リリース単位

| フェーズ | 機能 | 単体リリース可否 |
