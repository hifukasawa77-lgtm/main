# 要件定義書 — 源平争乱記 / Genpei Souranki

> プロジェクトハブ: [[genpei]] ／ 上流: [[genpei_基本構想]]（第3版・承認済み）／ 下流: `genpei_基本設計.md`
> 本書は基本構想の決定事項6件（同 第11節）を前提とし、**覆さない**。

---

## 1. 背景・目的

### 1.1 位置づけ

新規制作。既存ファイルの改修ではない。`genpei.html` を新設し、`sengoku.html`（1.3MB / 17,651行）には一切手を入れない。

前提となる確定事項（[[genpei_基本構想]] 第11節）:

| # | 決定 |
|---|---|
| A | 序章（1156保元 / 1159平治）は作らない。全シナリオが1180年以降の全国マップ |
| B | `sengoku.html` 不干渉。共通ライブラリ化もしない。コードは移植、画像は `assets/sengoku/` をその場参照 |
| C | タイトルは「源平争乱記 / Genpei Souranki」 |
| D | 1ターン＝1ヶ月 |
| E | 攻城戦あり（館・城郭の簡易戦。石垣・水堀・天守なし） |
| F | プレイ可能5勢力（平氏・鎌倉源氏・木曽源氏・甲斐源氏・奥州藤原氏） |

### 1.2 目的

1. **「名分を獲る」遊びを成立させる** — 兵力でも石高でもなく、院宣・宣旨・官位・三種の神器という政治的正統性を中核資源にする。
   平氏が全国の官位を握りながら滅び、頼朝が一度も京で戦わずに勝った構造を、そのままルールで再現する
2. **戦国風雲記のリスキンにしない** — 城・大名・知行という16世紀の枠組みを持ち込まず、国衙・荘園・御恩と奉公という12世紀の枠組みで作る
3. **既存資産を最大限に流用して制作コストを抑える** — 地図・GameKit・ヘックス戦・描画部品の移植で、新規制作の負担を「データとルール」に集中させる
4. **同じ盤面で違う体験を出す** — 同じ日本地図の上で、戦国風雲記とはまったく別の意思決定を迫る

### 1.3 スコープ外（今回やらないこと）

- 保元の乱（1156）・平治の乱（1159）のシナリオ化 — **決定事項A**
- `sengoku.html` の変更・リファクタリング・共通ライブラリ化 — **決定事項B**
- 承久の乱・鎌倉幕府の運営フェーズ（1192年以降）
- 内政の細分化（開発度・商人・茶会など戦国風雲記型の深い内政）— 12世紀は在地領主制であり、大名的な内政は存在しない
- マルチプレイ・サーバ連携・外部API利用
- 有料API（画像生成 / LLM）を用いたアセット生成 — **CLAUDE.md の禁止規約**
- 3D化・実写動画・外部音源の導入

| フレームレート | マップ表示・合戦とも **60fps を維持**（デスクトップ Chromium 基準）|
| 初回表示 | タイトル画面まで **3秒以内**。アセットは後読みし、未ロード時はフォールバック描画に落とす |
| 後読みの同時数 | 同時4枚・1枚60秒上限（戦国風雲記の `DEFERRED_LOAD_CONCURRENCY` / `DEFERRED_LOAD_TIMEOUT_MS` 方式を移植）|
| ページ重量 | `genpei.html` 単体で **1.5MB 以下**を目標。超える場合はデータの外部JSON化を検討する |
| ターン処理 | AI 5勢力＋第三勢力の1ターン処理を **1秒以内**に完了する |

### 3.2 ブラウザ・環境対応

- Chromium / Firefox / Safari の最新版。iOS Safari・Android Chrome を含む
- **`file://` で開いても動作する**（M-46）。GitHub Pages 上と同一の挙動になること
- デスクトップ（マウス＋キーボード）とタッチ（ピンチズーム・ドラッグパン）の両対応

### 3.3 保守性

- 単一 HTML（`genpei.html`）。フレームワーク不使用・ビルドツール不使用
- データ（シナリオ・武将・国・拠点）はロジックから分離し、`assets/genpei/` の JSON / CSV を正本とする
- **武将は必ず配列末尾に追加する。** 肖像枠を配列 index で配布するため、途中挿入は後続全員の顔が無言でずれる
- **`drawImage` の source-rect を画素値で直書きしない。** 矩形は「測った原寸サイズ」と対で持ち、描画時に実解像度へスケールする

### 3.4 セーブ互換性

- `SAVE_VERSION` を持ち、読み込み時に検査する。非互換なら破棄して新規開始とする（初版のため移行処理は不要）
- 破棄時はユーザーに理由を表示する（黙って消さない）

## 4. 制約・前提

### 4.1 既存資産の前提

| 前提 | 内容 |
|---|---|
| 地図 | `assets/sengoku/gpt/sengoku-japan-map-user-v1.webp`（1672×941）を**参照**する。複製しない。改変しない |
| 座標 | 拠点は**正規化 `mx,my`（0..1）**で持つ。参照先が別解像度で再エンコードされても壊れないようにするため |
| 国データ | `provinces.json`（65国・論理座標 1000×650）を `assets/genpei/` へ複製し、石高だけ12世紀相当へ置換する |
| コード | `sengoku.html` から読んで `genpei.html` へ移植する。import はできない（単一HTML構成）|
| エンジン | `gamekit/gamekit.js` を土台にする |

### 4.2 史実表現の前提

- 出典は『平家物語』『吾妻鏡』『玉葉』等の**著作権切れの古典**に限る。現代の研究書・小説・映像作品からの引用は行わない
- 人物の生没年は確認できたもののみを `{born, died}` に入れる。確認できない人物は役職名のみの扱いとする
- 実在人物の描写は史実の範囲に留め、現存する子孫・団体を貶める表現をしない
- 家紋は意匠として一般化しているものを用いる。特定団体の登録商標に当たるものは使わない
  → **Legal-Checker による確認を Evaluator 提出前に必ず通す**

### 4.3 バランス設計の前提

- **平氏は「名分が最高値で始まり削れていく」側**、**鎌倉は「令旨一枚から積み上げる」側**として設計する。初期兵力の多寡で難易度を作らない
- 木曽・奥州は高難度枠。史実どおり滅びやすいが、勝ち筋が存在すること
- AI の集計値（最大勢力の拠点数・所有者交代の頻度）は**乱数の種を固定しないため試行ごとに大きく揺れる**。
  バランスを語るときは1回の実行ではなく **5試行以上の平均**で見る（三国志・天下三分で得た教訓）
- 「兵を貯めて殴る」が支配的戦略にならないよう、兵糧の維持コストと恩賞債務の2つで歯止めをかける

## 6. 優先順位と分割方針

基本構想 第10節の Phase を要件IDへ対応させる。**Phase 1 の完了時点で「最後まで遊べる」状態**を作り、以降は体験を厚くする。
