# 03 個人情報・通信の秘密・外部送信・AI — フォーム・カメラ・ログ・外部API・端末内処理

現行: 個人情報保護法**2026-10-01版**。**施行予定の大改正（法律第56号）**: **2027-01-17**（一部）／**2028-07-16**（16歳未満の個人情報・課徴金・特定生体個人情報・連絡可能個人関連情報・未成年者の最善の利益 ほか新設31条規模）。
電気通信事業法は現行2026-05-27版、**2027-05-27に再改正予定**。ガイドライン・省令・告示は**コーパス未取込**（個人情報保護委員会・総務省の公表資料を WebFetch で確認する）。

## 1. まず「何が個人情報か・誰が事業者か」
- 個人情報の定義【個人情報保護法2条｜特定の個人を識別することができる】: 氏名・顔画像・メールアドレス（容易照合性）。**個人識別符号**（顔の特徴データ等）も含む。
- **個人関連情報**（Cookie ID・広告ID・IPアドレス等で、個人情報に当たらないもの）【個人情報保護法2条｜個人関連情報】: 第三者へ提供して提供先で個人データとなることが想定されるなら【個人情報保護法31条｜個人関連情報】で本人同意確認。
- **要配慮個人情報**【個人情報保護法2条｜病歴】: 病歴・障害・犯罪歴等。**取得に原則本人同意**【個人情報保護法20条｜要配慮個人情報】。心拍・体調の記録（health／heart-rate）は**医療情報に近い**ので、**端末内完結で送信しない**設計を明示する。
- **事業者性**【個人情報保護法16条｜事業の用に供している】: **個人でも、事業として個人データを扱えば個人情報取扱事業者**（件数要件は無い）。非営利の趣味サイトでも**フォーム・名簿・投稿**を持てば注意。

## 2. 事業者の義務（取得→利用→管理→提供→開示）
| 局面 | 条文 | 実務の着眼 |
|---|---|---|
| 利用目的を特定・公表 | 【個人情報保護法17条｜できる限り特定】【個人情報保護法21条｜本人に通知し、又は公表】 | プライバシーポリシーに目的を書く。**取得前の通知公表** |
| 目的外利用・不適正利用 | 【個人情報保護法18条｜利用目的の達成に必要な範囲を超えて】【個人情報保護法19条｜違法又は不当な行為を助長】 | 追加目的は**事前同意**。違法・不当な行為を助長する利用は禁止 |
| 適正取得 | 【個人情報保護法20条｜偽りその他不正の手段】 | カメラ・位置情報の取得は**明示と同意** |
| 安全管理・委託先監督 | 【個人情報保護法23条｜安全管理措置】【個人情報保護法25条｜委託先の監督】 | 外部API・クラウドへの送信は**委託先**として監督 |
| 漏えい等報告 | 【個人情報保護法26条｜漏えい等の報告】 | 要配慮・不正目的・1000件超等は**委員会へ速報・確報**、本人通知 |
| **第三者提供** | 【個人情報保護法27条｜本人の同意】 | **同意が原則**。例外: 委託・共同利用・法令 |
| **外国にある第三者へ** | 【個人情報保護法28条｜外国にある第三者】 | **外部LLM/クラウド（海外）**へ個人データを送るなら、同意または基準適合体制＋情報提供。**委託でも28条の対象になりうる（要確認）** |
| 開示等の請求 | 【個人情報保護法33条｜開示】 | 保有個人データに対する窓口を用意 |

## 3. 通信の秘密と**外部送信規律**（このリポジトリで見落としやすい）
- 【電気通信事業法4条｜秘密の保護】【電気通信事業法3条｜検閲の禁止】【憲法21条｜通信の秘密】。他人間の通信を媒介する機能（DM・掲示板・チャット）を持てば、**通信の秘密**・届出の要否（【電気通信事業法9条｜電気通信事業の登録】）が論点になる。
- **外部送信規律**【電気通信事業法27条の12｜情報送信指令通信】: 対象役務（総務省令で定める**利用者の利益に及ぼす影響が少なくない電気通信役務**）を提供する事業者が、
  **利用者の端末から外部へ情報を送信させる指令**（解析タグ・広告タグ・外部SDK・埋め込み・Webフォント読込で利用者情報が外へ出る等）を出すときは、
  **①送信される情報の内容 ②送信先 ③利用目的 を通知または容易に知り得る状態に置く**（同意・オプトアウト・必須情報の例外あり）。
  - **対象かどうかは総務省令・ガイドラインで判断**（SNS・掲示板・検索・動画共有・オンラインモール・メッセージ等のカテゴリ）。**自己の情報発信のみのポートフォリオは対象外となる可能性が高い**が、**ログイン・投稿・共有・コミュニティ機能**があれば対象になりうる（要確認）。
  - **安全側の運用**: 外部送信が発生するなら**プライバシーポリシーに送信先・情報・目的を列挙**（Google Fonts・CDN・解析・SNSボタン・外部API）。→ スキャナ `legal-scan.mjs` の「外部送信」欄。
- 「**端末内で完結**」を売りにする機能（カメラ・音声・位置・学習モデル）は、**実際にネットワークへ出ていないこと**を**検査（ネットワーク要求の観測）**で確かめ、画面にも明記する。

## 4. カメラ・マイク・位置・生体
- 顔画像・顔特徴データは個人情報（識別符号）。**サーバーへ送らない・保存しない・端末内で処理**する設計は、取得・提供の論点を大きく減らす。**同意のUI（許可前の説明）**を用意。
- 位置情報は**本人の同意**。距離計算のみで保存・送信しない設計を明記（聖地巡礼機能）。
- 生体由来のデータは**2028-07-16施行予定の改正**で「特定生体個人情報」の通知義務（新設21条の2）。**将来の設計に影響**。

## 5. 外部AI・LLM APIを使う場合（Workerの案内エージェント等）
- ユーザー入力が外部事業者（例: 海外のAI API）へ送られるなら、**①入力に個人情報を含めない注意** ②**送信先・目的の開示** ③**外国への提供**（28条）④**事業者の学習利用の有無**（無料枠は学習に使われうる）を整理。
- **履歴・ログの保存期間**を決めて公表。**入力を保存しない設計**が最も安全。
- AI推進法【人工知能関連技術の研究開発及び活用の推進に関する法律7条｜活用事業者】は**活用事業者の責務（努力義務）**。罰則は無いが、**適正利用の説明責任**の根拠。

## 6. 肖像・プライバシー・パブリシティ（法令の外の判例法理）
- 氏名・肖像の利用は【憲法13条｜幸福追求】に由来する人格権。**現存する実在人物**（推し活の対象を含む）をゲーム・画像・AIで扱う際は、**肖像権・プライバシー権・名誉権・パブリシティ権**を見る（判例: `obsidian-vault/04-Knowledge/rokuho-kenpo.md` 参照）。
  パブリシティ権は「**専ら肖像等の顧客吸引力の利用を目的**とする」場合（最判平成24年2月2日・記憶ベース）。
- **歴史上の人物**は自由（死者の名誉は【刑法230条｜死者の名誉】のとおり**虚偽の事実の摘示**に限る）。**子孫・遺族の感情は法的保護の外でも炎上リスク**。
- **生成AIで実在人物の顔画像**を作る・使うのは避ける（ディープフェイク・名誉・肖像・不競法）。

## 7. 未成年者
- 現行ガイドラインは**15歳以下は法定代理人の同意**。**2028-07-16に16歳未満の読替規定（新設40条の2）**が入る予定。**子供向けの機能（チャット・投稿・課金）を作るなら設計段階で**。
- 取引面は【民法5条｜取り消すことができる】。

## 8. 帰結
- **行政**: 個人情報保護委員会の指導・勧告・命令【個人情報保護法148条｜勧告】。**命令違反は刑事罰**【個人情報保護法178条｜拘禁刑】（法人両罰【個人情報保護法184条｜罰金刑】）。**課徴金は2028-07-16以降**（新設148条の3〜）。
- **民事**: プライバシー侵害の慰謝料（個人は小額でも件数で膨らむ）。【民法709条｜故意又は過失】【民法710条｜財産以外の損害】。
- **プラットフォーム**: アプリストア・ホスティングのポリシー違反（プライバシーポリシー欠如）。

## 9. 確認手順（スキャナ→人）
1. `node scripts/legal-scan.mjs --only external-send,pii-collection,sensitive-category` で**外部送信先・フォーム・カメラ/位置/音声・健康情報**を洗う。
2. `privacy.html` に**送信先と目的が列挙**されているか照合（スキャナが突合する）。
3. 未分類の外部ホストは `legal/knowledge/data/external-hosts.json` へ分類を追加（運営者・目的・送信される情報・個人情報該当性）。
4. 解釈が割れる（外部送信規律の対象か等）→ **YELLOW＋専門家確認**。
