# ZERO-1 デスクトップ版 × Obsidian Vault 連携 設計案

- 状態: **段階1・2を実装済み** / 2026-10-02（`zero-1-local-ai` のブランチ `ccr-527ff935-y15vln`）。段階3以降は未着手
- 対象: 別リポジトリ `zero-1-local-ai`（PC版・Ollama・React/TypeScript）。**実装はそちらで行う**。
  本書はこのリポジトリ側の知見（`zero-1-mobile.html` / `assets/js/zero1-tools.js`）を移植するための仕様
- 目的: ZERO-1 が Obsidian Vault の内容を**手元で**引いて答え、頼まれたときだけ**安全に**書き戻せるようにする

## 1. 何ができるようになるか

| # | 機能 | 例 | 優先 |
|---|---|---|---|
| 1 | Vault検索（読み取り） | 「この前のゲーム公開の判断理由は？」→ ADR・Dailyから該当箇所を引いて答える | 最優先 |
| 2 | 出典つき回答 | 回答の下に `[[0022-asset-reencode-safety]]` のようにノート名を出す | 最優先 |
| 3 | メモ追記（書き込み） | 「これメモして」→ `00-Inbox/` か当日の Daily へ**追記のみ** | 2番目 |
| 4 | 今日のDaily要約 | 「今日何やった？」 | 3番目 |

## 2. 連携方式の選択

| 方式 | 中身 | 長所 | 短所 | 判定 |
|---|---|---|---|---|
| **A. ファイル直読み** | Node（Electron/サーバ側）が Vault フォルダの `.md` を直接読む | 鍵が要らない・Obsidian を起動していなくても動く・依存ゼロ | Vault の場所を設定する必要 | **採用** |
| B. Local REST API | `https://127.0.0.1:27124/vault/...` | Obsidian の検索を使える | APIキー管理が増える・Obsidian 起動が前提・自己署名証明書 | 見送り |
| C. git 経由 | リモートの Vault を pull | 複数端末で同期 | 取得が遅い・コンフリクト | 同期は Obsidian Git に任せ、ZERO-1 は触らない |

**A を採る理由**: Vault は素の Markdown。ファイルを読むだけなら鍵も常駐プロセスも要らず、失敗点が最も少ない。
B を足す場合も、キーは `.env.local`（gitignore 済み）にのみ置き、クライアントコードに書かない（CLAUDE.md「APIキー」規約）。

## 3. 検索の作り方（モデルの手前で決定的に引く）

`zero-1-mobile.html` の知見をそのまま使う。

- **モデルに `tool_calls` を書かせない**。小型モデルは JSON 文字列を本文へ書くだけで、ツールが一度も発火しない。
  検索は**モデルより先に**、正規表現＋語の重みで確定させる
- **当たったときだけ足す**。Vault 全体を渡すとコンテキスト窓が埋まり、いまの質問が押し出されて見当違いの答えになる。
  上位 N 件・`budget`（文字数）で頭打ち。**無関係なら 0 文字**
- **`system` は 1 つに畳む**。2 つ目の system を途中に挟むとテンプレート（Qwen/Gemma 系）が先頭しか描かず、
  例外もエラーも出ないまま知識だけ届かない
- 曖昧なら**検索しない**。誤爆は「AIが急に的外れな資料を持ち出す」に見える

### 索引

1. 起動時（と Vault 変更時）に `.md` を走査。`.obsidian/` `.trash/` は除外
2. frontmatter（`type` / `tags` / `date`）を取り出す
3. **見出し単位**で分割（ノート全体を1塊にしない）。1塊の上限は約 800 字
4. 語の重み: 題名 > 見出し > 本文。`type: decision`（ADR）と `04-Knowledge/` を少し優先
5. 日本語はスペースで区切れないので **2-gram** で当てる（形態素解析器は入れない）
6. `[[wikilink]]` は出典表示と「関連ノート」の取り出しにのみ使う

## 4. 書き込みの安全策（追記のみ）

- 書けるのは **`00-Inbox/` と `01-Daily/YYYY-MM-DD.md` への追記だけ**。既存ノートの上書き・削除はしない
- **実行前に利用者へ確認**（書く先と内容を見せて「書く」を押させる）。モデルが勝手に書かない
- **パスは正規化して Vault 内に収まるか検査**（`..`・絶対パス・シンボリックリンクの外向き参照を拒否）
- ファイル名・見出しはモデル出力をそのまま使わず、許可文字へ落とす
- **モデルの出力から HTML を組み立てない**（`createElement` + `textContent` のみ）。Vault のノート本文も同様
- 書いた結果（パス・追記文字数）を画面に残す。失敗は理由と次の一手を日本語で出す

## 5. プライバシー（ここが一番重要）

デスクトップ版 ZERO-1 には**クラウドLLMの例外**がある（月 ¥3,000・`accounting/budget.md` の `ZERO1_API_LIMIT`）。
Vault の中身は個人の意思決定・学びなので、**クラウドへ流れる経路を作らない**。

- 既定は **ローカル（Ollama）のときだけ Vault を使う**。クラウドLLM選択中は Vault 検索を無効にし、画面にその旨を出す
- どうしても使いたい場合は、**フォルダ単位の許可リスト**（例: `03-Decisions/` のみ）を利用者が明示したときだけ
- Vault の場所・許可リストは設定画面へ。保存は localStorage 系なら try/catch（落ちても既定へ）
- 検索結果の本文をログ・クラッシュレポートへ書き出さない

## 6. Vault の境界（混ぜない）

| Vault | 主体 | ZERO-1 との関係 |
|---|---|---|
| `obsidian-vault/` | Claude Code 自身の永続メモリ（ADR・知見・Daily） | **読み取りのみ**で連携してよい（意思決定の想起に有用） |
| `claudechord-vault/` | エージェントパイプラインの成果物 | 連携しない（成果物の置き場でZERO-1の記憶ではない） |
| 利用者個人の Vault（新設） | ZERO-1 の「自分のメモ」 | **書き込みはここだけ**。`obsidian-vault/` へは書かない |

`obsidian-vault/` は Claude Code が SessionStart hook で自動想起する前提の書式で運用している。
ZERO-1 が書き込むと書式が崩れ、想起の質が落ちる。**書き込み先は別 Vault か `zero1/` サブフォルダに分離する**。

## 8. 受け入れ検査（`zero-1-local-ai` 側に作る）

「例外もエラーも出ないのに壊れる」系が中心になるので、**故障を仕込んで ✗ が出ること**まで確認する。

1. 日本語の質問で、正しいノートが上位に出る（合成Vaultで固定の正解を持つ）
2. 無関係な質問では **0 文字**しか注入されない（Vault全文が漏れない）
3. 注入量が `budget` を超えない
4. 注入しても `system` は 1 つのまま
5. クラウドLLM選択中は検索が**呼ばれない**（実際にリクエストを捕まえて本文が含まれないことを見る）
6. 追記は既存内容を壊さない（前後比較）。**上書き・削除は到達不能**
7. `../../etc/passwd`・絶対パス・外向きシンボリックリンクが拒否される
8. Vault 内のノートに `<img onerror=…>` を入れても画面で実行されない
9. Vault が無い／空／読めないときも画面が止まらず、理由と次の一手が出る
10. 故障注入：パス検査・クラウド時の無効化・budget のいずれを壊しても ✗ になる

## 10. 実装結果（2026-10-02）

- 実装: `zero-1-local-ai` の `app/vault-index.ts`（索引・検索）/ `vault-files.ts`（走査・追記）/ `vault-store.ts`（設定・キャッシュ）/
  `vault-guard.ts`（Origin 検査）/ `api/vault/route.ts` / `settings-vault.tsx`。検査は `tests/vault.test.mjs`（19項目）
- 設計からの変更点:
  - 検索は**サーバ側（`/api/runtime` 内）**で行う。クラウド分岐を通過した質問にだけ付くので、構造的にクラウドへは渡らない
  - 見出し単位の分割は見送り、既存の文書索引（段落優先の区切り）を再利用した
  - 書き込みは設定画面のボタンのみ（音声「メモして」は未対応＝モデル経由の書き込み道を作らないため）
  - クラウド時の許可リスト例外は作らず**完全に無効**（未決事項の既定）
- 設定: `.env.local` の `ZERO1_VAULT_DIR`（読む）/ `ZERO1_VAULT_WRITE_DIR`（足してよい。未設定なら読むだけ）
- 確認: 偽の Ollama を立てて通しで確認（当たる質問は注入・出典表示／無関係は 0 文字／不正な書き先は拒否／追記は直後に引ける）
- 既知: `zero-1-local-ai` の main 時点で、起動時JSが 645KB（上限 640KB）で `rendered-html` 検査が1件落ちている（本件の前から）
