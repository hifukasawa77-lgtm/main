# note 収益化 — 設計と判断の記録

## 結論（先に）

**自動化するのは「記事を書く」まで。「投稿する」は人が押す。**
貼る手間は週3分ほど。noteプレミアム（任意）の予約投稿を使えば、月1回15分にまとめられる。

```
毎週水 06:00 JST  /note-post が題材を選んで記事を書く → PR claude/note-post   ← 自動
     ↓（深澤がPRを承認・マージ）
                  node scripts/note-export.mjs で貼り付け用テキストを出す
     ↓
  ┌ 無料会員 ──── 毎週1回、1本貼って公開      （週3分）      ← 人
  └ プレミアム ── 月1回、4本貼って予約日時を入れる（月15分）  ← 人
     ↓
毎週               記事が公開される
```

## なぜ「完全自動投稿」にしなかったか

noteには**公式の投稿APIが無い**（2026年9月時点。将来の公開予定も未定）。
技術的には、ブラウザのセッションCookieを持って非公開のエンドポイント
（`/api/v1/text_notes` 等、有料記事は `pay_body` フィールド）を叩けば投稿できる。
実際にそれを解説した記事も複数ある。

採らなかった理由は3つ。

1. **規約リスクが収益の上限より大きい**。noteの利用規約は自動化を明示的に許可していない。
   アカウントが凍結されれば、それまでに積んだ記事・フォロワー・売上導線を**まとめて失う**。
   月数千円の自動化のために、資産そのものを賭ける取引になっている
2. **非公開APIは予告なく壊れる**。仕様変更で黙って落ちる。落ちたことに気づかない週が出る
3. **止める理由が無い**。投稿の自動化で浮くのは月十数分。リスクに見合わない

**この判断は覆せる。** 深澤が「規約を確認したうえで自動投稿まで行く」と決めるなら、
`scripts/note-export.mjs` の出力をそのまま投げる層を足すだけで届く。
その場合も**専用のサブアカウントで先に試す**こと（本体アカウントを賭けない）。

## 手数料 — 「500円の記事」は手取りいくらか

手数料は**2段階**で、単純な足し算ではない。

1. **事務手数料**（決済手段によって変わる）を販売価格から引く
2. その**残額に対して**プラットフォーム利用料10%を引く

（さらに振込時に振込手数料 270円／回）

| 決済手段 | 事務手数料 | 利用料 | 500円の手取り |
|---|---|---|---|
| クレジットカード | 5%（25円） | 残475円の10%（47円） | **約427円** |
| PayPay | 7%（35円） | 残465円の10%（46円） | 約418円 |
| 携帯キャリア決済 | 15%（75円） | 残425円の10%（42円） | 約382円 |

**手数料はnoteプレミアムでも下がらない。** 有料記事・メンバーシップの利用料は
会員種別に関わらず10%（定期購読マガジンのみ20%）。

## noteプレミアム（月500円）は前提ではない

本パイプラインは**プレミアム無しでも完全に成立する**。
プレミアムで変わるのは以下だけで、収益条件は変わらない。

| | 無料会員 | プレミアム（月500円） |
|---|---|---|
| 予約投稿 | ✗ | ✓（Webブラウザのみ） |
| 販売価格の上限 | 50,000円 | 100,000円 |
| 定期購読マガジンの申請 | ✗ | ✓ |
| コメント欄のON/OFF | ✗ | ✓ |
| **販売手数料** | **10%** | **10%（変わらない）** |

**加入する理由は「公開日に手を動かさなくてよくなる」ことだけ。**
総作業時間はほとんど変わらない（月1回15分 ≒ 週1回3分×4）。
違うのは、旅行中でも体調が悪くても記事が予定どおり出るかどうか。

- **プレミアム無し**: 毎週1回、`note/export/` のテキストを貼って公開ボタンを押す（1本3分ほど）
- **プレミアムあり**: 月1回、4本まとめて貼って予約日時を入れる（15分ほど）

**まず無料会員で始めて、週1回の公開が負担になってから加入すればいい。**
月500円は有料記事が月2部売れれば出る額なので、売れ始めてからで遅くない。

## 何が「売れる記事」か

noteの開発・AI領域で金を払われているのは、おおむね次の条件を満たすもの。
本リポジトリはこの4つを**すでに満たしている**（だから題材にする価値がある）。

1. **具体的な数字がある** — 「22体のエージェント」「検査20本」「1.6GB→264MB」。
   一般論には金が払われない
2. **失敗が書いてある** — 「3コミット費やして誤診した」が本体。成功談だけの記事は無料で足りる
3. **手元で再現できる** — コード・スクリプト・設定が実物として付いている
4. **他所に無い** — 実際に運用して踏んだ問題しか書けない内容かどうか

`obsidian-vault/03-Decisions/`（ADR 32本）と `04-Knowledge/` が、そのまま
この条件を満たすネタ帳になっている。`note/topics.json` はそこから起こしてある。

## 価格の方針

- **無料記事と有料記事を交互に出す**。無料が集客、有料が回収。有料だけ並べると誰も来ない
- 有料記事は **500円** を基準にする（100〜300円は単価が低く、1,000円超は初見では売れない）
- **有料ラインより上（無料部分）に、記事の価値が伝わる分量を置く**。
  最低800字＋結論の要約まで見せる。「続きが有料」だけの記事は返金申請の対象になる
- 価格は公開後も変更できる。売れなければ下げる、ではなく**まず無料部分を厚くする**

## やらないこと（禁止事項）

- **収益実績の誇張・捏造をしない**。「月◯万円稼げます」は、実績が無いなら書かない。
  `scripts/verify-note-articles.mjs` の検査#7が禁止語（不労所得・誰でも・必ず稼げる 等）を機械検出する
- **AIに大量生成させて数で押さない**。noteはスパム的な大量投稿を規約で禁じている。
  本パイプラインが**週1本**に制限しているのはこのため
- **他所の記事を要約して売らない**。一次情報（自分のリポジトリで起きたこと）だけを書く
- **有料APIを使わない**（CLAUDE.md の大原則）。記事生成はClaude Code自身が行い、追加課金はゼロ

## 収益の見込み（正直な数字）

**実績はまだゼロで、見込みの数字も持っていない。**
以下の「各5部」は**根拠のある予測ではなく、感触を持つための仮の数字**（2026-09-24時点）。
実際に売れ始めたら `note/publish-log.json` の実数に置き換えること。

仮に月2本の有料記事（500円）が各5部売れたとして、手取りは約4,270円／月
（クレジットカード決済・振込手数料を引く前）。
**この規模なら「自動収益」と呼べるものではない。**

このパイプラインの実際の価値は、金額より次の2つにある。

1. **リポジトリの知見が外に出る形式で棚卸しされる**（採用・受注の導線になる）
2. **ポートフォリオサイトへの流入が増える**（noteは検索に強い）

売上が伸びるのは、記事が積み上がって「この人の記事は当たりが多い」と認識されてから。
週1本を1年続けて50本。そこが最初の分岐点になる。
