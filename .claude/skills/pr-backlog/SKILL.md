# /pr-backlog — 未マージPRの棚卸し

Routine（週5本）は**深澤の承認制でPRに積む**設計なので、承認されないまま滞留すると
成果が本番に届かず、しかも古くなるほどコンフリクトで**マージ不能**になる。
2026-09-27 の /self-improve で 11〜67日滞留のPRが6本見つかった（PR #345 のADR番号0035〜0039は
別セッションが新設したADR 0035と衝突）。**棚卸しは提案まで。マージ・クローズは深澤が決める。**

## 手順（GitHub MCP を使う。`gh` は無い）

1. `mcp__github__list_pull_requests`（state=open）で一覧。各PRについて `pull_request_read` で
   mergeable 状態・CIの結論・最終更新を取る
2. 分類する:

   | 区分 | 判定 | 推奨 |
   |---|---|---|
   | 健全 | CI緑・コンフリクト無し・30日以内 | 承認待ちとして要約を出す |
   | 陳腐化 | main に対しコンフリクト／30日超 | main を取り込んで更新（自分のブランチのみ）or 閉じて作り直し |
   | 衝突 | 同じ番号のADR・同じファイルを触る別PR | 先に入れる順序を提案 |
   | 死蔵 | 内容が既に main に入っている | クローズを提案（根拠のコミットを添える） |
   | 赤 | CI失敗 | 原因を調べ、直せるものは直して報告 |

3. ADR番号の衝突を機械的に見る:
   ```bash
   ls obsidian-vault/03-Decisions/ | sed -E 's/^([0-9]+)-.*/\1/' | sort | uniq -d   # main 側の重複
   ```
   PR側の追加分は `pull_request_read`（files）で `03-Decisions/00NN-` を拾って main と突き合わせる
4. 提案を1つの表にまとめて深澤へ出す（PR番号・区分・滞留日数・推奨・理由）。
   成果物にするなら Vault の `01-Daily/` へ1節（例: `## PRバックログ棚卸し`）

## 守ること
- **マージ・クローズ・ブランチ削除をしない**（深澤の承認後のみ）。承認を得たらその範囲だけ実行する
- **他人（Routine以外）のブランチで履歴を書き換えない**（rebase / amend / force-push 禁止）。取り込みは merge で
- 更新した結果CIが赤くなるなら push せず、理由を報告する（`workflow` スキルの検査の反復コストを参照）
- 個別機能PR（#332/#316/#271 のような古い機能）は、**今の main に照らして今も要るか**を先に確かめる。
  古い前提のまま更新すると、既に方針が変わった機能を復活させる
- ローリングPR（`claude/*`）は1本が積み上がる設計。**滞留中は新しいコミットが積まれ続ける**ので、
  マージ前に最新のRoutine成果物が混ざっていないか確認する
