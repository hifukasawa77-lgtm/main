# /context-saver — コンテキスト消費を抑える作業規約

**目的**: 同じ結果をより少ないトークンで得る。CLAUDE.md「コンテキスト節約のルール」の実行手順版。
作業を依頼されたら、着手前にこの規約を頭に置く（読み込みが最大の消費源）。

## 0. 着手前の3問（30秒）
1. 触るのは**どのファイルの何行目付近**か？ → 分からなければ Grep で特定（Readしない）
2. 答えは**要約1〜2行**で足りるか？ → 足りるなら調査はサブエージェントに任せ、結論だけ受け取る
3. 必須検査（CLAUDE.md各節）は**どれ**か？ → 出力は要約だけ読む（下記§4）

## 1. 読む（最大の節約ポイント）
| やること | 方法 |
|---|---|
| 場所を探す | `Grep`（`output_mode: files_with_matches` → 絞ってから `content`）。`head_limit` を付ける |
| 中身を見る | `Read` に **必ず `offset`+`limit`**。対象行の前後50行（index.html等）〜200行が上限 |
| 全体像 | ファイル全読みせず `grep -n "^function \|^const [A-Z_]* =" FILE` で関数・定数の目次だけ取る |
| 同じ箇所を再読 | しない。直前に Edit した箇所の再確認 Read は不要（Edit が失敗すれば分かる） |
| 変更確認 | `git diff HEAD --stat` → 必要なファイルだけ `git diff HEAD -- FILE` |

- **`.claudeignore` 記載ファイル**（`shogi_rpg.html`・`gradius-1.html`・`galactic-assault.html`・`stamps.js` 等）は Read 禁止。grep + offset/limit のみ
- **巨大ファイルの目安**: `sengoku.html` 19,756行 / `beat_em_up.html` 6,872行 / `genpei.html` 4,872行 / `taihei.html` 4,219行。全読みは数万トークンを一撃で失う
- 画像・WebP・音声・JSON 大型データは中身を読まない（存在・サイズ・参照だけ確認）
- 補助スクリプト: `bash .claude/skills/context-saver/ctx-peek.sh FILE 'PATTERN'` — 該当行番号と「推奨 offset/limit」だけを出す

## 2. 出力を絞る（Bash）
- 長い出力になり得るコマンドは `| head -N` / `| tail -N` / `--stat` / `-q` / `--oneline -n 10` を付ける
- ログ・検査結果は**全文を出さず**、`| grep -E "✗|FAIL|Error|error" | head -30` と末尾サマリーだけ
- `ls -R` / `find .`（assets配下は数千ファイル）は禁止。`ls DIR | head` か `find DIR -maxdepth 1`
- `git log` は必ず `-n` 指定、`git diff` は `--stat` を先に

## 3. 書く（Edit優先）
- 既存ファイルは **Edit の小さな差分**。ファイル全体の Write 再出力は新規ファイル以外禁止
- 出力コードは変更箇所のスニペット（前後10行）。全体貼りは禁止
- 同じ編集を多数箇所に行うときは1件ずつ Read せず、Grep で行番号を出し Edit を連続実行（`replace_all` も活用）

## 4. 検査・テスト
- 必須検査（`verify-*.mjs` 等）は**実行する。ただし出力は要約だけ読む**（`2>&1 | tail -25`）。失敗時のみ該当箇所を追加で見る
- 検査を省略して節約しない（CLAUDE.md の必須チェックは品質ゲート。節約対象は「読み・出力」であって検証ではない）
- 動的テストのスクリーンショットは必要なときだけ1枚。連続撮影しない

## 5. サブエージェントの使い分け
- **使う**: 広い横断調査（数十ファイルを掘って結論だけ欲しい）→ `Explore`。読んだ中間ファイルが本体コンテキストに残らないのが利点
- **使わない**: 場所が分かっている小修正、1〜2ファイルの読み書き（起動コストの方が高い）
- 依頼文に「**結論と該当 `file:line` だけ、200字以内で返す**」と書く。ファイル全文の返却を禁止する
- エージェント間の受け渡しは「ファイルXのY行目付近をこう変更」の形式（CLAUDE.md準拠）。コードブロックへのファイル全体貼りは禁止

## 6. 会話の運び
- 回答は結論先行・短く。読んだ内容の再掲、作業の実況、選択肢の網羅列挙をしない
- 長い作業（目安: 大量の読み込みを2〜3往復した後）は、区切りで `/compact`（要約）を提案する。話題が変わるなら `/clear`
- 完了済みの計画・経過は1行に畳む（プランファイルは未完了タスクのみ保持）
- 同じ調査を繰り返さない。判明した事実（行番号・仕様）は以降のターンで使い回す。長期に残す価値があれば `obsidian-vault/04-Knowledge/` へ

## アンチパターン（やりがちな浪費）
- ✗ `Read sengoku.html`（引数なし）→ 約20,000行
- ✗ Grep を `content` モードで `head_limit` なしにワイド検索
- ✗ Edit 後に「念のため」全体を再 Read
- ✗ 検査スクリプトの出力を全文表示
- ✗ 場所が分かっているのにサブエージェントを起動
- ✗ 「念のため」他ファイルも先に読んでおく（必要になってから読む）
