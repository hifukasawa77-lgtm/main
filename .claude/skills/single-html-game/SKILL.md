# 単一HTMLゲーム制作

HTML ファイル1枚だけで完結する、本物のゲームに近い見た目と遊び心地のゲームを作る。

## 絶対ルール

1. **HTML 1ファイルで完結**。CSS/JS はすべてインライン。
2. **外部ファイル禁止**: 画像・音声・フォント・スプライト・CDN 画像など一切使わない。絵は Canvas 2D / SVG / CSS / three.js のプリミティブでコード描画、音は WebAudio(オシレーター/ノイズ)でコード合成する。外部依存を排除し、純粋なコードだけで全てを描画する。
3. **3D が必要な場合のみ** 無料の three.js(3JS)を使ってよい。2D で済むなら使わない。three.js を使う場合も CDN 読み込みか、単一ファイル化できるよう最小限にする(オフライン動作が必要ならライブラリをインライン埋め込み)。3D 以外のライブラリは使わない。
4. **キャラクター・名前・世界観はすべてオリジナル**。既存ゲーム/作品のキャラ名・ロゴ・固有名詞は使わない(ジャンルやゲーム性の参考にするのは可)。
5. **開いた瞬間から自動デモが動く**: タイトル/デモ画面で AI が自動プレイし、何かキーを押したら(またはクリックで)プレイヤー操作に切り替わる。ゲームオーバー後はデモに戻る。
6. **キーボードで遊べる**: 矢印キー/WASD + スペース/Z/X など。画面内に操作説明を表示。タブ非アクティブ時はポーズ、音は初回入力後に開始(autoplay 制限対策)。
7. **最重要・最後の一行**: 完成したら **自分でブラウザで動かして確認し、壊れているところを直してから出す**。確認前に納品しない。

## 品質の目安(「本物のゲーム」らしさ)

- 固定タイムステップのゲームループ(`requestAnimationFrame` + 累積 dt)、60fps で安定。
- 見た目: 統一された配色、影/グラデーション/パララックス、パーティクル、画面シェイク、ヒットストップ、スコア/ライフ/ステージ表示のHUD。
- 手触り: 加速/減速・慣性、コヨーテタイム、入力バッファ、当たり判定の甘め調整、効果音(WebAudio 合成)とBGM(簡易シーケンサー)。
- 進行: タイトル → プレイ → ゲームオーバー/クリア → リトライ。難易度が徐々に上がる。ハイスコアは `localStorage`(失敗しても動くよう try/catch)。
- キャンバスはウィンドウに合わせてリサイズ(論理解像度を固定しスケール)、`image-rendering` 等でくっきり表示。

## 作業手順

1. 依頼からジャンル・世界観・オリジナルのキャラ名/タイトルを決める(ユーザーが指定していなければ自分で決めて進める)。
2. 1ファイルに構成: `<style>` / `<canvas>` / `<script>`。コードは 入力 → 状態 → 更新 → 描画 → 音 → AI(デモ) の順に整理。
3. 自動デモ用 AI は、プレイヤーと同じ入力インターフェース(仮想キー状態)を操作する形で実装すると、操作系とデモが一致して壊れにくい。
4. **検証(必須)**:
   - ブラウザで `file://` で開く(Claude Browser ペイン等。`mcp__Claude_Browser__navigate` で `file:///...` を開く)。
   - コンソールエラー/警告を `read_console_messages` で確認、外部リクエストが無いことを `read_network_requests` で確認(three.js 以外の外部通信が出たらNG)。
   - スクリーンショットで描画を確認し、デモが自動で進行しているか、数秒~数十秒観察する。
   - キー入力(`key`/`type`)で操作に切り替わるか、移動・攻撃/ジャンプ・被弾・ゲームオーバー・リトライを実際に試す。
   - 必要に応じてビューポートを変えてレイアウト崩れを確認。
   - 不具合(描画崩れ、操作不能、フリーズ、デモが詰まる、音が鳴らない、NaN、当たり判定の抜け等)があれば直して**再度**確認する。問題が出なくなるまで繰り返す。
5. 納品: ファイルパスを示し、遊び方(操作キー)・タイトル・キャラ名を簡潔に伝える。**確認した内容と、確認できなかった点(例: 音は実聴不可)を正直に報告**する。壊れたまま出さない。

## アンチパターン

- 画像/音声ファイル、`<img src>`、`new Audio("x.mp3")`、Web フォント、外部 CSS/JS(three.js 以外)の使用。
- 既存IPのキャラ・名前の流用。
- 動作確認をせずに「完成」と報告する。
- デモが無く、静止したタイトル画面で入力待ちになる。
