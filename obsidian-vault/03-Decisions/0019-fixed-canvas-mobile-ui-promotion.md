# 固定CanvasのモバイルUI対策をgame-devへ昇格＋lint検査#8を位置ベース検査へ強化

## 背景・問題
PR #256 マージ後の main に、07-17 Daily の新セクション2件（スマホメニュー視認性改善・文字はみ出し是正）が別ブランチ経由で追記されており、未昇格の学び2件がマーカーなしで残っていた:
1. **固定canvas＋stretchのモバイル拡大は「パネルごと拡大＋入力逆変換」が定石**（部分的な文字拡大はレイアウト破綻。中心基準の相似変換で描画と入力を同じ係数で包み、既存スケール機構は描画中に無効化）
2. **固定canvas UIの文字あふれは「箱に合わせて字を縮める」のが最終防衛線**（drawButton 共通処理に measureText によるラベル横幅フィットを1箇所）

さらに lint 検査#8（0018で修正済み）がこれを検出できなかった: マーカーの「存在」しか見ておらず、**昇格済みマーカーの後ろに追記された**学びセクションを見逃す（同型の偽陰性が 07-01 にも存在: 地の文の「昇格済みフッターを追加」がマーカー扱い）。

## 決定
1. **game-dev/SKILL.md** — 新セクション「固定Canvas UIのモバイル可読性対策」: パネルごと拡大＋入力逆変換・ラベル横幅フィット・Playwright pointer:coarse 強制での実機再現検証
2. **harness-lint.sh 検査#8** — 位置ベース検査へ強化: 最後の学び行 > 最後のマーカー行 なら「追記された未昇格の学び」として警告（行番号付き）
3. **self-improve/SKILL.md 手順0** — 検査#8の説明を位置比較の実態に追随（07-01の学び「仕組みを増やしたら説明文書まで更新対象」の適用）
4. 07-01 / 07-17 に反映済み/昇格済みマーカーを追記して警告を解消

## 理由
- 学び2件は固定解像度canvasゲーム全般（本リポジトリの標準構成）に効く一般則で、モバイル対応の再発問題。宛先は「狭く効かせる」原則で game-dev へ。
- 検査#8はマーカー運用が「ファイル単位→セクション単位→末尾追記」と進化するたび偽陰性を出してきた。位置比較は追記型の運用に対して構造的に頑健で、実際に強化直後へ 07-01 の見逃しを1件検出した。

## 影響・トレードオフ
- マージ由来でDailyに学びが追記されるフロー（複数ブランチ並行）でも昇格漏れが機械検出されるようになった。
- 位置比較は地の文のマーカー語（「昇格済みフッターを追加」等）を依然マーカー扱いし得るが、最後の学びより前にある場合のみで、末尾追記の実運用では影響が小さい。誤検知した場合も△非ブロッキング。
