# 0038 — 手で更新する登録簿には、機械の見張りを付ける（ZERO-1 デスクトップ版）

## 背景

深澤さんの依頼で、ZERO-1 デスクトップ版（`zero-1-local-ai`）を対象に自己改善ループを回した。

検査 1080件はすべて緑。CLAUDE.md と `docs/開発の注意.md` が指すファイル・コマンド・
数値（page.tsx 2,000行／起動時JS 640KB）にもずれは無かった。
**ずれていたのは登録簿だけだった。**

`scripts/doctor.mjs` の `TRACKED_FEATURES`（`ZERO-1診断.cmd` が
「その機能が反映されているか」を答えるための一覧）に8件しか登録が無く、
直近に足した**9機能が丸ごと漏れていた**。同じ9機能が `README.md` からも漏れていた。

決まりは `docs/開発の注意.md` §2 と `doctor.mjs` のコメントの**両方に書いてあった**。

## 決定

1. **9機能を登録**（8→18件）。目印が実際のビルド（dist）に在ることを全件確認
2. **`tests/tracked-features.test.mjs` を新設。** 設定パネル（利用者から見える機能の単位）を
   1枚足したら必ず落ちる。登録するか、理由を書いて免除するかを強制する
   - 免除は**1枚ずつ・理由つき**（[[0036-exemptions-are-per-line]]）
   - 目印は**コメントを落としてから**探す（コメントの文字を認めると診断が嘘を言う）
3. **README は機械検査で縛らない。** 目印はUIの文言で、README の言い回しとは別物。
   無理に揃えると誤検知の出る検査になる。代わりに、登録漏れで鳴る検査の
   **失敗メッセージ**へ README 更新の指示を書いた

## 根拠

- 登録が足りないことは**何も壊さない**（検査は緑、画面も動く）。壊れるのは
  「診断が答えられない」という、使う人が困ったその瞬間だけ。完全に無症状なので、
  文章の決まりでは守れない——実際に、書いた本人が9回続けて忘れた
- 故障注入5件のうち1件がすり抜け、**この検査自身の弱点**（コメントの文字列を
  目印として認める）を捕まえた。直して5件すべてで✗を確認
- 縛らない判断も残した。「厳格さは明示した箇所だけに掛ける」（verifier 原則#2）を、
  今回は README に対して適用した

## 影響

- `ZERO-1診断.cmd` が18機能について「反映されているか」を答えられるようになった
- 次に機能を足したとき、登録を忘れると**必ず落ちる**
- **残り（2026-09-14 中に解消）**: ZERO-1 には harness-lint 相当の横断lintが無く、
  文書のずれは手で監査するしかなかった。監査の結果ずれはゼロだったが、
  **その監査は毎回誰かが手でやらないと効かない**。
  `tests/docs-references.test.mjs`（4件）として ZERO-1 の検査へ組み込んだ——
  ①指すファイルの実在 ②書いたコマンドの実行可能性
  ③**書いた数値とコードの一致**（page.tsx 2,000行／起動時JS 640KB）
  ④package.json が実在するスクリプトを呼ぶか。
  いちばん危ないのは③で、数値はずれても何も壊れないため
  「2,000行まで」と読んだ人が2,500行書いて検査で初めて落ちることになる。
  故障注入6件（うち1件は「読み取り自体が壊れて偽の緑にならないか」）で✗を確認
