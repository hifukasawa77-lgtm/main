# 0027: 外部（ChatGPT）由来の大規模改善提案は5フェーズに分割して実装する

## 背景
深澤がChatGPTに幕末風雲記のレビューを依頼し、「①藩論（思想）②京都政局
③外国勢力④人物相関⑤歴史イベント分岐」という、ゲームの根幹に関わる
5項目の改善提案（ChatGPT共有リンク経由）を持ち込んだ。5項目まとめて
一度に実装すると、実装量が大きく不具合の切り分けが困難になるリスクが
あった。

## 決定
`AskUserQuestion`で「①から順に、実装→動作確認→PRレビューという
既存の進め方を踏襲するか／5項目まとめて一度に実装するか」を確認し、
前者（順次実装、推奨）を選択。以降、深澤の「続きをお願いしたい」の
都度1項目ずつ実装し、同一PR（#325）へ積み増す形で進めた。

- ①藩論システム → ②京都政局 → ③外国勢力 → ④人物登用リッチ化 →
  ⑤歴史イベント分岐、の順で実装。各フェーズはPlaywrightで実測検証
  してからコミット
- 後続フェーズは前フェーズの状態を再利用する設計にした
  （例: ⑤の坂本龍馬×薩長同盟ボーナスは④の`state.recruitedRyoma`を
  参照、⑤の桜田門外の変倍率は開始直後の選択`state.blackshipsChoice`
  を参照）ことで、個々の機能が独立した継ぎ足しではなく互いに連動する
  一体感のある実装になった
- 最終PRは1本にまとめたが、マージは深澤が実機確認してから都度指示
  する運用にした（機能追加のたびに逐一マージ確認を挟むかは深澤の
  「マージして下さい」の頻度に委ねた）

## 理由
- 5項目まとめての一括実装は差分が肥大化し、深澤による実機レビューが
  1回に集中してフィードバックの粒度が粗くなる
- 既存のCLAUDE.mdの精神（コンテキスト節約・変更は最小単位で検証）とも
  整合する
- 段階実装のほうが、後続フェーズが前フェーズの資産（藩論値・京都影響力
  など）を参照する設計にしやすく、機能同士の有機的な連動を後から
  無理なく足せる

## 副産物
実装中にネイティブ`<dialog>`のトップレイヤーが`position:fixed`要素を
隠す不具合を発見・修正した（詳細: [[native-dialog-toplayer-pitfall]]）。
また、data.js内の未使用だった肖像画付き人物データ（64名、
`assets/portraits/`と1:1で一致することを事前検証）を発掘し④で活用した
——「未使用に見えるデータでも実装前に存在確認する価値がある」実例。

## 現状
5項目すべて実装・PR #325としてmainへマージ済み（2026-08-23）。
