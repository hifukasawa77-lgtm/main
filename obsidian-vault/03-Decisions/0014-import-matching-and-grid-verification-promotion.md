# 0014 外部データ取込マッチングとグリッド整合機械検証の知見をスキルへ昇格

## 背景・問題
直近2件のバグ修正で、実証済みの再利用可能な汎用パターンが Daily Note に「学び（汎用パターン）」として残ったまま未昇格だった:
1. **2026-07-14**: CSV取込の件数不一致・既存データ損失バグ（sengoku.html / 358a7a0）。原因は「主キー一致→曖昧キーフォールバック」型マッチングに claimed チェックが無く、複数行が同一エンティティへ潰れたこと。
2. **2026-07-16**: 攻城戦ヘックスと背景画像の不整合（sengoku.html / 8f0cf85）。目視スクショ比較では検出できず、座標変換を再現した機械的オーバーレイ描画とBFS到達性チェックで初めて確定・修正できた。

Dailyに置いたままでは次のCSV取込実装・グリッドゲーム実装時に自動では効かない。

## 決定
以下を各スキルへ差分追記で昇格（すべて追加型・既存ルールの変更なし）:
1. **coding/SKILL.md** — 新セクション「外部データ取込のマッチング」: ①曖昧キーフォールバックには claimed（割当済み）チェック必須 ②行→エンティティID割当は最初に一括計算し全フェーズで共用（行数＝件数の保証）③報告件数と一覧実件数の突き合わせ検証
2. **game-dev/SKILL.md** — 新セクション「グリッド×背景アート整合と到達性の機械検証」: ①整合確認は座標変換を再現した機械的オーバーレイ描画で行う（目視スクショ比較禁止・グリッド層は等倍固定）②通行レイアウト変更時はBFSで「破壊込み到達可」と「無傷時封鎖」の両側検証（ヘックスの斜め隣接は目視で隙間を見落とす）③HUD凡例は描画分岐から機械的に照合できる形で保守

## 理由
- どちらも実バグの根本原因と検証手法として実証済みで、特定タスクに閉じない一般則（CSV取込は他ツール/管理画面でも、グリッド検証は将棋系・攻城戦系で再利用可能）。
- 宛先は「狭く効かせる」原則に従い、データ取込＝coding（コード設計の正）、グリッド/到達性＝game-dev（Canvasゲーム実装の正）へ分離。dynamic-tester への重複記載は見送り（検証は実装時に行う設計指針であり、実装者が読む場所に置く）。

## 影響・トレードオフ
- 次回以降、CSV/外部データ取込の実装時に claimed チェックと一括割当が最初から指示として効き、同種のデータ損失バグの再発を防ぐ。
- グリッド×背景のゲーム（攻城戦・盤面系）で「目視でOKに見える」誤配置・通行隙間を機械検証で捕捉できる。
- スキル本文が伸びるが、Dailyの学びを恒久ルールへ降ろすことで recall コンテキストは削減方向（従来方針と同じ）。
