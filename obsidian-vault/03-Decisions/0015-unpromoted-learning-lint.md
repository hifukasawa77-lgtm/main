# 0015 未昇格の学びを含むDailyをharness-lint検査#8で機械検出（警告のみ）

## 背景・問題
2026-07-16の /self-improve 13thで、07-14・07-16の「学び（汎用パターン）」が未昇格のまま残っていたのを手作業の遡り点検（`grep -L 昇格済み`）で発見した。同点検で07-13の計測メタ知見・07-09のプロセス知見の昇格漏れも見つかった。昇格漏れは「学びが毎回recallコストのまま残る」ループの穴であり、手作業点検は忘れられる。

## 決定
- harness-lint に**検査#8**を追加: 学びセクション（`## 学んだこと` / `学び（汎用パターン）`）を含むDailyに `昇格済み`/`反映済み`/`昇格しない` マーカーが無ければ**警告（△）**を出す。
- 警告は **exit codeに影響しない非ブロッキング**とする。昇格要否の判断（一般則か一回限りか）はLLM＋深澤の作業であり、lintで機械的に強制できないため。CIも失敗させない。
- ベースライン整備として旧Daily（06-22/06-28/06-30）へ反映済み確認マーカーを追記した（学び自体は当時のADR・知見ノート経由で反映済みと確認）。
- 併せて /self-improve SKILL.md 手順0の検査一覧と手順1（遡り点検）を更新。

## 理由
- 「手作業で繰り返した監査は機械化して恒久化する」既定路線（[[0007-harness-lint-automation]]）の適用。
- ✗（是正必須）ではなく△（点検リマインド）としたのは、未昇格Dailyは書かれた直後は正常な状態であり、/self-improve 実行時に降ろすのが正規フローのため。ブロッキングにすると新しいDailyを書くたびlint/CIが赤くなる誤設計になる。

## 影響・トレードオフ
- 次回以降の /self-improve 手順0で昇格漏れが自動的に列挙され、遡り点検の抜けがなくなる。
- 検出は見出し書式（`## 学んだこと` / `学び（汎用パターン）`）に依存するヒューリスティック。second-brain スキルの書式ルールに従わない自由記述の学びは拾えない（その場合も手順1の目視点検でカバー）。
