# 0023 検査スクリプトの健全性を横断ルール化し、Daily骨組み生成を機械化する

## 背景・問題

`/self-improve` 15回目。未昇格のまま残っていた5日分（07-28 / 08-01 / 08-05 / 08-07 / 08-09）を点検したところ、
性質の異なる2つの構造的な問題が見えた。

1. **検査が「赤くならない」ではなく「現実と違うことを言う」形で壊れる**（08-05）。
   `i18n-check` / `seo-audit` / `a11y-audit` の3本が同時に嘘の答えを返していた
   （日本語タイトルの全ページを「英語のみ」と誤警告、`index.html` のOGPを完全欠落と誤判定、
   正しい `aria-hidden="true"` を不合格に）。同じ性質は案内エージェントの話題ガード（08-07）にもあり、
   そちらは「強すぎるガードが正常な質問まで無言でブロックする」という**緑のまま機能低下する**形で出た。
   これまで「負のテストを行う」ルールは `/self-improve` スキル内（harness-lint 用）にしか無く、
   リポジトリ全体の検査スクリプトには効いていなかった。
2. **Dailyの無い作業日を手で埋める作業が3回目**（[[0016-daily-coverage-lint]] → [[0020-perf-cost-placement-and-canvas-layout-promotion]] → 今回）。
   検査#9 が「漏れの検出」を機械化した一方、**埋める側は毎回手作業**のまま残っていた。

## 決定

- **検査の健全性を横断ルールへ昇格**: `.claude/skills/coding/SKILL.md` に新Skill
  「検査スクリプトの健全性 (Verification Script Integrity)」を追加し、負のテスト必須・
  ガードの両建て検査・`[warn]` の腐り・C locale の空振り・「同じ根でも表現形が違うと既存lintに引っかからない」を集約した。
- **Daily骨組み生成を機械化**: `.claude/skills/second-brain/backfill-daily.sh` を新設。
  git log から `## 作業記録（遡及）` と触れた領域までを生成し、**`### 学び` は空欄で残す**
  （機械が書く部分とLLM/人が書く部分を分離する）。既存Dailyは上書きしない。
- 併せて、当日点検で見つかった残り5件の学びをそれぞれ最も狭く効く宛先へ昇格した（Daily 2026-08-16 の表を参照）。
  うち `agents/legal-checker.md` への「出自の追跡可能性」は確認手順に新しい段（手順3）として入れた。

## 理由

- 検査の嘘は**気づけない**種類の劣化で、しかも今回のように監査3本が同時に腐っていても
  誰も止められなかった。ルールの置き場所を `/self-improve`（≒週1回しか読まれない）から
  `coding`（コードを書くたびに参照される）へ移すことで、検査を**書く瞬間**に効く。
- backfill は「検出はできるが是正は手作業」という非対称を解消するもの。
  同じ手作業が3回出た時点で、その作業自体が昇格対象だと判断した。
- 学び欄を機械で埋めない（＝空で残す）のは、commit message から学びを**捏造しない**ため。
  記録の正は git log であり、学びは当時の差分を見た人・LLMだけが書ける。

## 影響・トレードオフ

- `coding` スキルが1セクション増える。デバッグ/リファクタ/取込/性能に次ぐ5本目で、粒度は揃っている。
- backfill が生成する Daily は薄い（コミット件名＋領域のみ）。recall hook は**最新のDailyだけ**を
  読むため、薄いDailyが最新になると想起の情報量が落ちる。当面は許容し、
  最新日が薄いまま残る場合は本文を手で足す運用とする。
- backfill 実装中に **`--since` はコミッタ日付・`%ad` は作者日付**という取りこぼしを踏んだ
  （08-11 / 08-17 が対象から消えた）。1回のログ取得を作者日付でグルーピングする形で解消。
  harness-lint 検査#9 も同じ組み合わせだが、あちらは過剰に警告する側へ倒れるため据え置いた。
