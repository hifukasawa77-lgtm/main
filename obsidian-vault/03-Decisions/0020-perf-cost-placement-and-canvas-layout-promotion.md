# 0020 前処理コストの置き場所とCanvas絶対座標レイアウトの整合をスキルへ昇格

## 背景・問題

/self-improve 16th の harness-lint で△警告が2種出た。

1. **07-18 のマーカー後追記2件が未昇格**（検査#8）— agent-evolve 手動起動で得た学び（`/stats` へ到達できない／Vault追記のマーカー依存が無音失敗する）が昇格されずに残っていた。
2. **07-19〜07-25 の7営業日が「作業コミットあり・Dailyなし」**（検査#9）— 戦国風雲記の大規模改修と三国志・天下三分の新規立ち上げが、別ブランチ・別セッション中心に進み Vault へ書き戻されていなかった。

特に 2 のコミット履歴を精査したところ、**同一テーマで3回手戻りした地図描画の性能改修（PR #273→#274→#275）**と、**モバイルでだけ発現するレイアウト崩れの連続修正（PR #277/#279/#281）**という、再発性の強い2系統が見つかった。再発＝ルール化されていない証拠であり、最優先の昇格候補と判断した。

## 決定

7営業日分を遡及Daily化したうえで、再利用可能な一般則を以下へ昇格した（すべて追加型の差分追記。既存の振る舞い変更なし）。

**coding スキル / パフォーマンス最適化**（新規ブロック「前処理コストは『毎フレーム／静止のたび／ロード時に一度』のどこに置くか」）
- 重い前処理（畳み込み等）を**カメラ静止のたびに全域へ焼く**のは体感ワーストの配置。平均FPSに現れず「なんとなく重い」として報告される。静止時に置いてよいのは変換のみの軽い焼き直しだけで、生成コスト数十ms以上はロード時1回へ移す。
- 軽量化で画質が落ちたら「品質を諦める」ではなく**高品質中間ビットマップをロード時に一度だけ作る**。プリスケール倍率はメモリとのトレードオフなので、採用/却下の理由をコード内コメントに残す。
- **補償ハックは原因を直したら撤去する**。品質不足を誤魔化す小細工は上流改善後に害へ転じる。

**coding スキル / 外部データ取込のマッチング**
- 取込成功後は派生キャッシュを**明示破棄**する（キャッシュキー変化やTTL任せにしない）。データ更新経路とキャッシュ無効化を同じ関数内に置く。

**game-dev スキル / 新セクション「Canvas絶対座標レイアウトの整合」**
- 条件分岐でレイアウトが変わるなら、同じパネル内の**全要素**の座標を同じ条件で見直す（`py+(img?400:140)` 型の片側更新漏れが即重なりになる）。検証は分岐の全組み合わせでスクリーンショット。
- 衝突回避レイアウトの占有矩形は**実際の描画寸法（スケール適用後）**で予約する。描画倍率とレイアウト計算倍率の一致は、拡大率を導入した時点で必ず確認する。
- ワールド座標は等倍のまま保持し、拡大は `ctx.scale` と占有矩形計算に反映する。

**game-dev スキル / 固定Canvas UIのモバイル可読性対策（既存セクションを強化）**
- オーバーレイ表示中は canvas外の固定HTML UIを隠す（z-indexでは指の当たり判定が残る）。
- タッチではホバー前提UIを無効化し、情報表示は明示的な当たり判定にヒットした時のみに限定する。

**agent-evolve スキル / 弱点収集**
- `curl` 終了コード非ゼロ・`http_code=000` は worker障害ではなく**実行環境の外向き遮断**。切り分けてPR提案欄へ上げ、鮮度改善だけの空回りを繰り返さない。

**second-brain スキル / 書式ルール**
- 追記はマーカー依存にしない。`sed`等のマーカー挿入はマーカー不在時に**無音失敗**して記録が消えるため、末尾追記を基本とし、挿入した場合は `grep` で存在確認する。

## 理由

- 3回の手戻り（#273→#274→#275）は「軽くする→粗くなる→補償を外す」という典型的な振り子で、**前処理をどのタイミングに置くか**という単一の設計判断で説明できる。この判断軸をスキルに書けば振り子ごと回避できる。
- モバイル限定の崩れ（#279）は PC（倍率1）で無症状なため発見が構造的に遅れる。「倍率を入れたら倍率の一致を確認する」を明文化するのが最も安価な予防になる。
- モーダル重なり（#281）とスマホ配置崩れ（#279）は表面的には別バグだが、**Canvasにレイアウトエンジンが無い**という同一原因のため、1つの新セクションに束ねた。
- 07-18 の2件は宛先が明確（該当スキルのその手順）で、最も狭く効く場所へ置けた。

## 影響・トレードオフ

- coding / game-dev スキルが各1セクション強化・1セクション新設で肥大化するが、いずれも実バグで実証済みの内容であり、参照はスキル単位のため常時コンテキストは増えない。
- 遡及Daily 7本を追加した。recall hook が全文投入するのは最新1本のみのため、常時コンテキストへの影響は 2026-07-25.md のみ。古い6本は意図的に簡潔化した。
- **昇格しないと判断したもの**: 個別の倍率調整（07-19）・差別化5系統やエージェント追加等の個別施策（07-20/07-21/07-22）は一回限りで再利用性がない。「記録の空白は別セッション作業で起きる」（07-25）は運用頻度の問題でハーネス指示の宛先がないため、深澤への報告（/self-improve を週1で回す）に留めた。
