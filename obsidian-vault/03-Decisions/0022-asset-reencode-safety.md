# 0022 アセット再エンコードの安全策と、マップ描画の機械検査を追加

## 背景・問題

`e55d88b 戦国マップ用アセットの読み込みを軽量化` の副作用で、深澤から
「アセットした画像を読み込めていない」の報告（スクショ2枚）。実際には別種の不具合が2件
同時に出ていた。

1. **縮小したアセットの切り出しが画像外へ出た**
   海賊・馬牧・国人マーカーとリソースアトラスは、生成画像の白い余白を除くため
   `drawImage` を**元画像のピクセル座標**で切り出していた（例 `[80,80,1094,1094]`）。
   アセットを 1254px → 256px へ縮めた結果この矩形が画像外へ出て、Canvas 側で
   切り詰められアイコンが消えた。実測の塗り面積は海賊2.4% / 国人3.5% / 南蛮寺セル**0%**。
   `img.onload` は成功するため 404 もコンソールエラーも出ず、**無言で絵だけが消える**。

2. **後読みアセットが帯域を食い尽くした**
   アセットは300枚超・計638MB。これを一度に全部要求していたうえ、同コミットで
   後読み画像のタイムアウトが外れていた。結果シナリオ導入絵（1枚2〜3MB）が
   「読み込み中… / Loading」のまま待たされ、施設・城グラフィックも届かず、
   その間ずっと仮のベクター図形（＝白い箱）が表示されていた。

## 決定

**実装（sengoku.html）**
- 切り出し矩形は「それを測った原寸サイズ」と対で保持し、描画時に実画像の解像度へ
  スケールし直す（`scaleSrcRect` / `RESOURCE_MARKER_ATLAS_REF`）。今後どの解像度へ
  再エンコードしても壊れない。
- 後読みは同時4枚まで＋1枚60秒上限（`DEFERRED_LOAD_CONCURRENCY` /
  `DEFERRED_LOAD_TIMEOUT_MS`）。**タイムアウトを外さない**——応答の返らない1枚が
  同時実行枠を永久に占有し、後続が一切進まなくなるため。
- シナリオ導入絵6枚は一斉ではなく1枚ずつ順に先読み（`prefetchScenarioIntroArt`）。

**検査（scripts/verify-map-assets.mjs 新設）**
①GPT_ASSETS 全件の疎通 ②切り出し矩形が実画像に収まるか ③実際の描画関数での塗り面積。
③は**施設画像を外したフォールバック経路**まで測る。修正前24件検出・修正後0件を確認済み。

**文書（CLAUDE.md）**
「戦国風雲記の必須チェック」へ `verify-map-assets.mjs` を追加し、上記3点を箇条書きで明文化。

## 根拠・学び

- **アセットの縮小は「切り出して使っている箇所」を道連れにする**。画像差し替えは一見
  ローカルな作業だが、source-rect を画素値で直書きした描画があると解像度変更が即バグ化する。
  しかも失敗が無音（404もエラーも出ない）なので、CIでもレビューでも捕まらない。
- **「読み込めていない」の半分は帯域の食い合いで、404ではない**。localhost 実測でも
  導入画面表示までの転送量 265MB・1.2秒 → 制限後 17.8MB・0.1秒と12倍差。並列要求数と
  優先順位を先に疑うこと。
- **フォールバック描画があると、不具合は primary が生きている環境で再現しない**。
  手元では画像が即着するためフォールバック経路を一度も通らず、修正前後のスクショが
  同一に見えて誤読しかけた。`ASSETS.img` から該当キーを削って強制的に再現させたところ、
  深澤のスクショと完全一致した。**フォールバックを持つ描画は、それを強制する再現手順と
  セットで検査する**。
- **塗り面積は「描画ボックス基準」で正規化しないと閾値が引けない**。キャンバス全体基準で
  測った初版は正常アイコンまで8.9%と出た。ボックス一杯になる size を渡すと
  正常25〜47%・事故時0〜11%と明確に分離した。
