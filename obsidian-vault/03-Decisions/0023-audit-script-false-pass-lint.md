# 0023 監査スクリプトの「偽の✓」を静的検査で恒久化（harness-lint 検査#14）

## 背景・問題

`/site-proposal` が2週連続で無痕跡終了した原因を切り分けるため、同スキルが依存する4本の監査スクリプトを手動実行したところ、**2本が壊れたまま合格側の結果を返していた**ことが判明した。

1. **perf-audit**: `printf ... | python3 - <<'PY'` の形で、python本体をstdin（`-`）から読ませながらパイプでも対象リストを流していた。ヒアドキュメントがパイプを上書きするため `sys.stdin` は空になり、**「0ページ計測、1MB超過 0 件 ✅」を出し続けていた**。修正後に実測すると **95ページ計測・1MB超過8件**、`index.html` は **22.9MB**、`zelda_like.html` は11.3MB。
2. **i18n-check**: `grep -cP '[\x{3040}-\x{30ff}\x{4e00}-\x{9fff}]'` が C locale（ANSI_X3.4-1968）で `character code point value in \x{} or \o{} is too large` を全行に吐き、`grep -c` の結果が常に **0**。日本語タイトルが「日本語なし」と判定され、`[warn]title日本語のみ` が一度も出ていなかった。

どちらもエラーではなく**合格として現れる**ため、実行しているのに何も見ていない状態が長期間気づかれない。ADR [[0013-release-check-scripts-exclusion]]（壊れた正規表現は✗でなく偽の✓を出す）の再発である。

## 決定

- 両スクリプトを修正した。perf-audit は対象リストを環境変数（`PERF_TARGETS`）で渡し、**対象0件なら明示的に異常終了**する。i18n-check は PCRE パターン先頭に `(*UTF)` を付ける。
- harness-lint に**検査#14**（ブロッキング✗）を追加し、`.claude/**/*.sh` から次の2パターンを静的検出する:
  - `| python3 - <<` （ヒアドキュメントによるstdin奪取）
  - `grep -P` 系で `\x{...}` を使いながら `(*UTF)` が無いもの
  自スクリプトとコメント行は除外する（罠を説明した文章が自分で偽陽性を出すため。検査#7と同じ扱い）。
- perf-audit SKILL.md に**計測の限界**を明記した: 集計は `src`/`href` の静的走査なので、**JS内の文字列から動的に読むアセットを数えない**。Canvasゲームは大半がこの経路のため過小評価になる（sengoku.html はレポート約4MBだが、シナリオ導入画像だけで別途約15.6MB）。ゲームHTMLの評価では `du -sh assets/<ゲーム名>` を併用する。

## 理由

- 静的検出にしたのは、監査スクリプトを毎回実行して結果を解釈するのは重く、**この2つの罠は書いた瞬間にソース上で判別できる**ため。実行時検証ではなく「書いた時点で弾く」ほうが安く確実。
- ✗（ブロッキング）にしたのは、これがワークフローのリマインド（△）ではなく**スクリプトの破損**そのものだから（[[harness-maintenance-patterns]] の2段重大度の基準に従った）。
- 負のテストを実施済み: 両パターンを含む一時ファイルを置いて2件とも✗が出ることを確認し、削除して✓に復帰することまで見た。

## 影響・トレードオフ

- 検査#14が見るのは**既知の2パターンだけ**で、「偽の✓」全般を防げるわけではない。新種を踏むたびに1行ずつ足していく性質の検査（検査#7・#12と同じ運用）。
- `(*UTF)` は GNU grep の PCRE 前提。`grep -P` 非対応環境では別途 python3 へ寄せる必要がある。
- perf-audit が初めて実数を返したことで、**サイト側に未対応の重量問題が表面化した**（`index.html` 22.9MB ほか計8ページが1MB超）。これは本ADRの範囲外で、asset-optimize 案件として深澤へ報告済み。
- 教訓の一般形（計測対象0件を成功にしない／エラー出力を `|| true` で握りつぶさない／新規検査には負のテスト）は [[harness-maintenance-patterns]] の「bash 検査スクリプトの罠」へ追記した。
