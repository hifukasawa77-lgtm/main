# 戦国の野望の合戦バグ群から得た実装/検証パターンをサブエージェント定義・スキルへ昇格

## 背景・問題
2026-07-17 の Daily に、sengoku.html の合戦バグ修正・委任AI強化で実証された再利用可能な学びが `♻️ 未昇格` マーカー付きで残っていた:
1. **画像トレース地形の遠近は縦位置で補正**（敵が地平線に浮く不具合）— 色/テクスチャでは平地の遠近を判別できず、行インデックスに下限を噛ませるのが最も堅牢。
2. **勝敗・占拠は陣営の絶対基準で書く**（防衛攻城戦の開幕即敗北バグ）— `playerSide` 相対の判定は対称ゲームで片側だけ壊れる。派生フラグの二重基準OR（`battleType==='siege' || 城Lv>=3`）も同系統。
3. **AI計測は勝ち筋(reason)別に集計＋到達性BFSで詰み判定**（委任攻城AIが天守を落とせない）— 勝率だけでは質的欠陥を見逃す。
4. **シーン直起動の検証パターン**（07-17内で3回反復）— page.evaluate から `buildGameState()`＋`changeScene` を直接叩けばUI操作なしで任意シーンを検証できる。headless は RAF が絞られるためスクショ前に draw を明示呼びする。

また、harness-lint 検査#8 がこの 07-17 を警告できていなかった: ①学び検出が `^## 学んだこと` 見出しのみで inline の `**学び（…）**` を拾えない ②ファイル内に別セクションの「昇格済み」が同居すると未昇格分が不可視化される、の2段の取りこぼし。

## 決定
すべて差分追記（追加型・既存ルールの変更なし）で昇格:
1. **game-dev/SKILL.md** — 既存「グリッド×背景アート整合と到達性の機械検証」へ2項目追記（トレース地形の縦位置補正／AI計測はreason別＋到達性BFS）＋新セクション「対称ゲームの判定は陣営の絶対基準で書く」（絶対基準の不変条件・派生フラグ単一ソース）
2. **dynamic-tester エージェント定義** — 注意事項へ「シーン直起動でスモークテストを超えた検証」「headless RAF絞り→draw明示呼び」を追記
3. **dynamic-test/SKILL.md** — 注意へ RAF罠を追記（詳細はエージェント定義へ誘導）
4. **harness-lint.sh 検査#8** — `未昇格` マーカーを最優先で警告（昇格済みマーカー同居でも取りこぼさない）＋学び検出パターンを `学び（` へ広げ inline 太字型も拾う

## 理由
- 1・2 は実バグの根本原因として実証済みで、盤面/対称ゲーム全般に効く一般則。宛先は「狭く効かせる」原則で game-dev（Canvasゲーム実装の正）へ。
- 4（検証パターン）は同日中に3回反復＝再利用の実証。検証者が読む dynamic-tester エージェント定義へ（実装指針ではなくテスト技法のため game-dev ではない）。
- lint 修正は「未マーカー点検の機械化」（ADR 0015）の穴埋め。マーカー運用がセクション単位になった実態に検査を追随させる。

## 影響・トレードオフ
- 次回以降、対称ゲーム・画像トレース地形・AI自動指揮の実装/検証で同種バグの再発を指示レベルで防げる。dynamic-tester はスモークテストを超えたシーン単位検証の武器を持つ。
- 検査#8 は「未昇格」の文字列がある限り毎回△を出すため、/self-improve での昇格（またはマーカー除去の判断)が促される。誤検知が増える方向だが非ブロッキング（△）なので運用コストは小さい。
