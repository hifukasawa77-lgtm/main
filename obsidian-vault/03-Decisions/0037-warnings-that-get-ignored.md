# 0037 — 繰り返し無視される警告は、警告のほうを疑う

## 背景

harness-lint 検査#9（作業したのに Daily が無い日）が、**同じ4日を3回続けて**警告していた
（2026-09-09 / 09-10 / 09-13 の /self-improve）。私はそのたびに読み飛ばしていた。

調べたら、4日のうち**2日は学びを記録していた**——`04-Knowledge/` の
[[same-value-read-from-three-places]]（09-07）と [[success-messages-that-lie]]（09-08）。
検査が `01-Daily/` しか見ていなかったので、記録済みの日まで咎めていた。

残る2日（09-01・09-05）は本当に Vault に痕跡が無く、**学びは CLAUDE.md へ直接書かれていた**。

## 決定

1. **検査#9 の「記録された」の範囲を広げる。** Daily があるか、**その日に
   `04-Knowledge/` か `03-Decisions/` のノートを新しく作っているか**、どちらかで緑。
   - **広げるのはここまで。** CLAUDE.md の編集まで数えると、無関係な編集で素通りする
     （[[0036-exemptions-are-per-line]]「免除は必要な分ぴったりに切る」をそのまま適用）
   - 負のテスト3方向で確認: 記録が無い日は咎める／判定を常に真にすると素通りする／
     読む先を別ディレクトリに変えると記録済みの日まで咎める
2. **学びを CLAUDE.md や docs へ直接書いた日も、Daily を1本残す**
   （何を学び、どこへ書いたかの1〜2行）。→ `.claude/skills/second-brain/SKILL.md`
3. 09-01・09-05 を遡って記録し、学びの行き先（CLAUDE.md の該当節）を明記した

## 根拠

- **無視される警告は、あるだけ害。** 本物が混ざったときも一緒に流される。
  「誤検知が出る検査は必ず無視されるようになる」（verifier 原則#2）の実例が、
  誤検知ではなく**判定範囲の狭さ**として出ていた
- 3回無視したのは注意力の問題ではない。**警告が指していた「不足」の半分は実在しなかった**。
  直すのは人の習慣ではなく、検査が「記録された」と認める範囲のほうだった

## 影響

- 検査#9 の警告が0件になった（残っていた2日は本当に記録が無く、遡って埋めた）
- verifier 原則#2 に「繰り返し無視されている警告は、警告のほうを疑う」を追記
- **この /self-improve の主目的はこれ1件**。前回（09-10）以降、新しい作業は無く、
  新しい学びも無い。**無いときに作らない**のも、このループの一部だと考える


## 続き（2026-09-14）— 広げた翌日、その検査自身が誤検知を出した

判定を広げた翌日、`2026-09-12` が「作業コミットあり・記録なし」と警告された。
中身は **`github-actions[bot]` の「Jリーグ順位表を更新 [skip ci]」1件だけ**——
自動更新で、学びも決定も生まれない日だった。

**この決定文で「無視される警告は、あるだけ害」と書いた、その検査自身が
翌日に誤検知を出した。** 気づけたのは、翌日もう一度回したから。

- 除外は**作者がボットであること1点だけ**に切った。
  メッセージの `[skip ci]` や変更先の `data/` で広げない——人が同じ印を付けた
  本物の作業まで見逃す（[[0036-exemptions-are-per-line]]「免除は必要な分ぴったりに切る」）
- 実測で確認: 直近14日の65コミット＝人61＋ボット4。**人のコミットは1件も落ちていない**
- 負のテスト: 除外を外すと 2026-09-12 の警告が戻る
