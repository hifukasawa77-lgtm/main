# 0041: /self-improve 6回目の実運用（koma_ken.htmlの法務再評価漏れを発見・legal-checker.mdへ原則追加）

## 背景
前回（2026-10-25、ADR 0040）のPR #369は、本セッション開始時点で未マージのまま7日経過していた。
`git merge origin/main`（36コミット差）を実行し、コンフリクトなしで完了した。

## 確認したこと

### 1. 検査#9で遡及発見: koma_ken.htmlの法務評価が後続コミットで無効化されたまま公開中
検査#9が指摘した7日分（10-26〜11-01）のうち、10-26〜10-31は新作「降魔七星剣」（`koma_ken.html`、
深澤自身の直接コミット）の実装期間だった。各コミットを確認する過程で、重大な法務上の抜け漏れを
発見した:

- **2026-10-26**: Legal-Checkerが`koma_ken.html`を一次スクリーニング（`legal/knowledge/
  08-this-repo-ledger.md`）。前提条件「画像・音声・外部通信なし」のもとRED 0 / YELLOW 4で判定
- **2026-10-30**: コミット`542e4a8`で`assets/koma-ken/audio/`（17MB・BGM14曲＋SFX）を追加。
  `assets/koma-ken/review/README.md`の記述から、これは1988年Taito『不動明王伝』のNSF
  （NES Sound Format）から FFmpeg/libgme で音声化した**原曲そのもの**（権利者からの許諾は
  未確認）であることが判明した
- **現在時点**: 公開中の`https://hifukasawa77-lgtm.github.io/main/koma_ken.html`は、一次
  スクリーニングの前提が崩れた状態のまま、未許諾の原作楽曲・効果音を配信し続けている

### 2. 構造的な原因
法務スクリーニングは**その時点のスナップショット**に対して行われ、対象ファイルへの**その後の
変更**を追跡する仕組みが無かった。`legal-checker.md`には「配布形態が変わったら再評価」の原則が
既にあったが、「評価の前提（無いと判定した要素）が後から追加された」ケースは明文化されていな
かった。これは`verification-counts-the-wrong-thing`系の学びとも通じる——**評価の有効期限（前提の
生存確認）を持たない検査・審査は、前提が崩れても緑のまま**という一般的な脆弱性パターン。

### 3. 対応（範囲の判断）
- `self-improve`はハーネス指示への昇格を扱うスキルであり、個別コンテンツの法務判断（削除・
  差し替えの実施）は権限外と判断し、**実施していない**
- `legal-checker.md`に原則を1件追加（「評価の前提が後から崩れたら無効」）。追加型の注意書き
  のみで既存ルールの変更ではないため、AskUserQuestionでの承認は不要と判断した
- `legal/knowledge/08-this-repo-ledger.md`の追記ログへ2026-11-01付でRED判定を追記し、
  深澤への報告事項として明記した（Legal-Checkerエージェント自身による再スクリーニングを推奨）
- Dailyバックフィル7件（10-26〜11-01）を作成。10-30の記録に本件の詳細を記載

### 4. harness-lint・検査結果
- `harness-lint.sh`: ✅（検査#9の7件は全て遡及記録済み。検査#8・#15も問題なし）
- `verify-legal-knowledge.mjs`: ✅（既存の△警告は全て本件と無関係な法令改正の鮮度の件。
  新規の引用形式不備なし）

### 5. PRバックログ（簡易確認・大きな変化なし）
PR #271は102日滞留で変化なし。本PR（#369→今回で6回目）も7日経過していた。

## 決定
1. `legal-checker.md`に原則「評価の前提が後から崩れたら無効」を追加
2. `legal/knowledge/08-this-repo-ledger.md`に2026-11-01付でRED判定のエントリを追記
3. Dailyバックフィル7件（10-26〜11-01）
4. 深澤への報告: koma_ken.htmlの原作音源が未許諾のまま公開中。Legal-Checkerの緊急再
   スクリーニングを推奨（本ADR・該当Dailyに詳細）

## 影響・トレードオフ
- 本ADRでは音声ファイルの削除・差し替えを実施しない（深澤の判断を要する実質的な意思決定のため）。
  公開が継続する間、権利者からの申立てリスクは残る
- 「評価の前提の生存確認」を機械検査化する余地はあるが（例: スクリーニング時点のファイルハッシュを
  記録し、変化を検知したら警告）、今回は初回発生のため文章への昇格のみに留めた。再発したら
  Verifierへ機械検査化を検討する
