## 学んだこと・気づき
- **負のテスト（故障注入）自体が「別の理由」で通ることが本セッションで4回発生した**: 落ちているサーバへ向けたSSRF検査、短すぎる画像応答が別の最小長チェックに掛かった、検査素材が消えるべき領域の外にあった、静的検査の正規表現が別箇所にマッチしていた。いずれも「検査は✗になったが壊した箇所とは無関係」というパターン。→ `coding` スキルへ昇格
- **ファイル分割（page.tsx → 別コンポーネント）のたびに、対象ファイルを直接 readFile する検査が静かに漏れた**（D工程・履歴パネル切り出しの2回とも再発）。`clientSource()` のようなディレクトリ実列挙ヘルパーに検査を寄せて解消。→ `coding` スキルへ昇格
- Web Speech API の `continuous:false` はブラウザ実装依存の無音判定に頼っており、息継ぎで打ち切られる。`continuous:true` + 自前の沈黙タイマーで直したが、それでも「認識が予期せず終わる→空のまま作り直す」経路で未確定分（interim）が消える別バグが残っていた。**表示（React state）だけ引き継いでも、送信は別のローカル変数を見ていたため直っていなかった**——React の state は次の再描画まで反映されず、ブラウザAPIのコールバック内で読んでも古い値のままになる（クロージャの罠）。この教訓はReact/TS固有で、本ポートフォリオ（フレームワーク不使用方針）には直接は効かないため今回は昇格見送り（zero-1側の作業ログとしてのみ残す）
