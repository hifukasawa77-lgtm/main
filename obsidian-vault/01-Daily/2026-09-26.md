## 学んだこと
- 構造化データは「書いた＝正しい」ではない。**実装していない機能（サイト内検索）や画面に無いFAQを申告すると、例外もエラーも出ないまま検索エンジンに嘘をつく**。申告は実装と突き合わせて消す
- GitHub Pages のプロジェクトサイト（`/main/`）では `robots.txt` はドメイン直下でないため無効。sitemap は Search Console から送る
- `assets/js/app.js` と `sitemap.xml` は CRLF。Pythonの `open(...,'w')` で読み書きすると**全行が差分になる**（17,266行の差分で気づいた）。書き戻し後に `git diff --stat` で行数を必ず見る
- `main.css` は SW の cache-first 経路なので、CSSを足したら `?v=` を上げないと再訪者に届かない

## 学んだこと
- **node:sqlite は外部キーが既定で有効**（SQLite 本体の既定は無効）。PRAGMA を消す故障注入はすり抜ける＝故障になっていない。検査は「OFF にしたら落ちるか」で確かめる
- 版上げの取り消し（ROLLBACK）の検査は、**版の最初の1文で落とすと何も確かめていない**（半端な表が残る余地が無い）。終盤で落ちるように仕込む
- zero-1-local-ai の `vinext dev` はこのクラウド環境では node:sqlite が `operation not permitted` で動かない（既存の /api/history も同様）。実機と同じ `npm run build && npm run start` で確かめる
- 画面から型だけ import しても、サーバ専用モジュール経由で node:sqlite へ辿り着くと client-safety 検査が落ちる。共有する形は純粋な `*-types.ts` に置く

## 学んだこと
- **HTTPの状態番号だけで相手を決めつけない**。検証環境のプロキシが返した403を「Notion連携の権限不足」と表示していた。Notion の失敗には必ず `code` が付くので、無ければ「届く前に断られた」と言う（推測で原因を書かない）
- 「リサーチしてもらった」は「リサーチして」を含む。過去を指す言い回しを先に外してから依頼の語を判定する
