## 学んだこと
- 構造化データは「書いた＝正しい」ではない。**実装していない機能（サイト内検索）や画面に無いFAQを申告すると、例外もエラーも出ないまま検索エンジンに嘘をつく**。申告は実装と突き合わせて消す
- GitHub Pages のプロジェクトサイト（`/main/`）では `robots.txt` はドメイン直下でないため無効。sitemap は Search Console から送る
- `assets/js/app.js` と `sitemap.xml` は CRLF。Pythonの `open(...,'w')` で読み書きすると**全行が差分になる**（17,266行の差分で気づいた）。書き戻し後に `git diff --stat` で行数を必ず見る
- `main.css` は SW の cache-first 経路なので、CSSを足したら `?v=` を上げないと再訪者に届かない

## 学んだこと
- `open(p, encoding='utf8', newline='')` で読み書きすればCRLFは保たれる（前回の全行差分の再発防止）
- `.reveal` 付きの要素は IntersectionObserver で表示されるまで opacity:0。スクショ検証は要素そのものを画面内へ入れて待ってから撮る（真っ白な画像を「壊れた」と誤診しない）

## CIで落ちた: CSPハッシュの陳腐化
- `index.html` の CSP は **JSON-LD を含む全インラインscriptのsha256** を持つ（`scripts/security-csp.mjs`）。
  構造化データを1文字変えただけでCSPが古くなり、GitHub Actions `security` が赤になった
- 直し方: `node scripts/security-csp.mjs --write`。**`index.html` / `blog*.html` / `dashboard.html` のインラインscript（JSON-LD含む）を触ったら必ず実行**
- release-check・dynamic-test では検出されない（ブラウザは data block の JSON-LD を実行しないので、画面は壊れない）。昇格候補: release-check に `security-csp.mjs` を組み込む
