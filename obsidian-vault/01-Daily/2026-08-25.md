# 2026-08-25

## 幕末風雲記の拠点座標が地図とずれていた（14件中6件が海の上）

深澤から「地図に対して各拠点の位置がずれている」と報告。実測すると
鶴岡・新潟・長岡・佐賀・鹿児島・高知の6件が完全に海の上に置かれていた。

原因は2つ:

1. **座標そのものが絵地図の陸と合っていなかった**。`assets/maps/strategic-japan.png`
   は写実CGの絵地図で、`sengoku-japan-map-user-v1.webp` とは別物（同じ1672×941だが
   陸の位置が数%ずれている）。前回の修正（70523ed）は目視で当てただけだったので残っていた。
2. **表示領域が `cover` で左右を切り取る**のを勘定に入れていなかった。674×488 の枠に
   1672×941 を cover で敷くと可視範囲は x 11.2〜88.8% しかなく、九州西岸が枠外へ出る。
   そのため佐賀・鹿児島を東へ寄せる形になり、地図とのずれが固定化していた。

### やったこと
- 地図画像を陸/海マスク化して 14 拠点を実測配置し直した（陸率 0.8〜1.0）
- `background-position` を `38% center` にして九州西岸を可視範囲へ入れ、
  `projectPoint()` に `MAP_FOCUS` を追加して CSS と同じ切り取りを掛けるようにした
- `scripts/verify-bakumatsu-map.mjs` を新設（陸判定・切り取り位置の一致・見切れ・ラベル重なり）
- 1行だけの `bakumatsu-map-fix.css` を `bakumatsu.css` へ畳んで削除

### 学び
- **拠点のずれは例外もエラーも出さない**。「起動して例外0件」の動的テストは完全に素通りする。
  絵の上に何かを置く機能は、置いた先の画素まで見る検査を書かないと必ず再発する
- **`cover` は座標系を静かに壊す**。CSSの `background-position` と JS の投影は同じ値を
  持つ二重管理になる。二重管理を許すなら一致の機械検査までが1セット（ADR 0028 と同じ轍）
- **写実CGの絵地図は画素単位の陸/海判定が効かない**。谷影・街道・河川が海色に落ちるので
  ブロック平均（13×13px）で判定する。しきい値を上げると今度は雲を陸と誤判定する
- 故障注入で確認: MAP_FOCUS を CSS とずらす／高知を海へ動かす、どちらも検出できた

## 追記: 新UI（fc47324）とのマージで `cover` が破綻していた

デプロイのため main へ取り込もうとしたら、その間に「幕末風雲記の基本画面を新UIへ刷新」が
main へ入っていてコンフリクト。CSS/HTMLは新UI側を全面採用し、座標修正（game.js）だけを残した。

そこで新しい問題が出た。新UIの `.map-stage` は固定676×490ではなく**画面サイズで伸縮する**
（実測 692×658〜900×722、縦横比0.9〜1.5）。地図画像は縦横比1.78なので `cover` だと
**横が最大48%切り取られ**、1440×900では萩・佐賀・鹿児島がフレームの外へ出て押せなくなっていた。

拠点のx範囲は 13〜72（=59%幅）なので、`background-position` をどこへ寄せても救えない。
`cover` → `contain` に変え、`projectPoint()` も `Math.max` → `Math.min` を選べるよう
`MAP_FIT` 定数を追加した（上下に余白は出るが、全拠点が必ず見える方を採る）。

### 学び
- **可変レイアウトでの `cover` は「見えない領域」を画面サイズの関数にする**。固定サイズの頃は
  可視範囲を一度計算すれば済んだが、伸縮するようになった瞬間、ある画面幅でだけ拠点が消える
  バグに化ける。地図上の全要素を必ず見せる要件があるなら `contain` 一択
- **UI刷新は座標系の前提を黙って書き換える**。fc47324 は座標に一切触れていないのに、
  拠点の可視性を壊していた。座標を持つ機能のCSSを触ったら、必ず該当の検査を回すこと
- 検査は「実際に描かれた拠点の矩形中心」を見るように直した。マーカー `i` の位置を見ていると
  UI改修で `.node` のラベル構成が変わった瞬間に偽のFAILを出す（今回それを踏んだ）
