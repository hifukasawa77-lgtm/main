## 追記: ZERO-1の深掘り監査（2回目のディープダイブ）

深澤の「ZERO-1について再度、ディープラーニングして欲しい」を受けて、ZERO-1の実装全体を
監査した。機能ではなく**品質ゲートが実際に効いているか**を見た結果、静かに効いていない
ものが3系統見つかったので直した（`zero-1-local-ai` 1b3d703）。

### 見つかったもの
1. **`npm test` が9本あるテストのうち1本しか走らせていなかった**。`node --test
   tests/rendered-html.test.mjs` と直書きされており、表情ケア42件・音声23件・回答ガード33件
   など**157件が一度も走っていなかった**。全部緑に見えるので誰も気づかない
2. **`tsc --noEmit` が常時7件エラーで、どのnpm scriptにも組み込まれていなかった**
   （＝型検査が事実上死んでいた）。4件は実コードの型漏れ、3件はCloudflareの型欠落
3. **ESLintのエラー16件が放置**。うち1件は実害あり — 履歴の行が `<button>` の中に
   `<i role="button">` を入れる形で、**キーボードだけでは会話を削除できなかった**

### 学んだこと・気づき
- **「テストが全部通っている」は「テストが全部走っている」を意味しない**。走る範囲を
  検査で固定しないと、名指し実行がいつのまにか一部だけになっても緑のままになる。
  → 対策として「`npm test` がテストを全部走らせているか」自体を検査に追加した
  （既存ADR [[0023-verification-integrity-and-daily-backfill]] の実例が1つ増えた形）
- **恒常的に赤い検査は、組み込まれずに死ぬ**。`tsc --noEmit` はエラー7件のまま誰も
  実行しない状態だった。0件にして初めて `npm run check` に載せられる。
  「赤いまま放置」は「検査が無い」と同じ
- **`role="button"` を付けた非対話要素はキーボードから押せない**。例外もエラーも出ず、
  マウスを使う人にだけ動いて見える。lintは検出できていたが、エラーを無視していたので届かなかった

### 昇格を見送ったもの
- 上記はいずれも既存のADR/スキル（検査の健全性）の範囲内で、ポートフォリオ側の
  ハーネスへ新しく足すべき指示は無いと判断。ZERO-1 の README へ「変更したときの検査」
  節を新設して、そちらで担保した
