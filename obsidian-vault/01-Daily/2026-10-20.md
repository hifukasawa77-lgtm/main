# 2026-10-20

## ZERO-1（別リポ `zero-1-local-ai`）の深掘り点検 — 3回目
深澤の「ZERO-1について再度、ディープラーニングして欲しい」。8月の1回目は品質ゲートそのものが
効いていなかった（検査9本中1本しか走っていない等）。今回はゲートは全部健全だったので、
**ゲートが見ていない所**を探した。結果、枠（iframe）の隔離に穴が1つ。

- 発見: モデルが書いたコード・添付由来の中身を動かす `sandbox="allow-scripts"` の枠に
  **`allow-same-origin` を足しても、全2,092件の検査が1件も落ちない**。
  足すと枠が画面と同じオリジンになり、会話・保管庫・`.env.local` の鍵で動く ZERO-1 自身のAPIへ
  枠の中のコードから届く。例外もエラーも出ず、解析も試し実行も成功したまま
- この決まりは `app/code-trial.ts` の注意書きに**前から書いてあった**。機械が一度も見ていなかっただけ
- 対処: `tests/sandbox-isolation.test.mjs`（3件）＋ `docs/開発の注意.md` §44・§15の表へ登録。
  故障注入7通りすべてで ✗ を確認。`npm run check` 緑（2,095件）。
  ブランチ `claude/sandbox-isolation-guard-2026-10-20`（4607921）へ push 済み・PRは未作成

## 学んだこと・気づき（**未昇格**）
- **故障注入は「注入が当たったこと」を確かめてから走らせる。** 空振りした注入は
  「検査が落ちない」という結果を返すが、それは**守りが無い証拠ではなく、何も壊していない証拠**。
  今回これで危うく「課金上限の天井（¥5,000）は守られていない」と**嘘の指摘**を出すところだった
  （`Math.min(…, Math.floor(ceiling))` に `Math\.min\(([^,]+), ceiling\)` を当てて空振り。
  当て直したら実際は2件落ちた＝ちゃんと守られていた）。
  偽の緑（検査が無いのに在ると思う）の裏返しで、**偽の赤**＝効いている守りを「無い」と報告する事故。
  本ポートフォリオでも同型を一度踏んでいる（`oshi-research` のクロージャ経由で注入が空振り）→ **二度目**
- **カバレッジの数字を結論にしない。** `node --test --experimental-test-coverage` で
  `api-budget.ts` が「行59%・関数16.7%、`decideCall` も `checkBeforeCall` も未到達」と出たが、
  検査は実際に19関数すべてを呼んでいた。数字から立てた仮説（道具が壊れている／合算が効かない）は
  最小再現で**2つとも否定**された。結局、守りが効いているかは**故障注入でしか分からなかった**
- **import の grep でカバレッジを推し量らない。** 「検査から import されていない86ファイル」を
  出したが、`price-source` は `reconcile.ts` 経由の再輸出で実際には検査済みだった
