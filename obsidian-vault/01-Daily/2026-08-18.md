# 2026-08-18

## 太平風雲記: モバイル横画面ゲートを追加

- `taihei.html` はモバイル縦画面で 1440×810 (16:9) の Canvas が `max-width:96vw` だけで縦に大きく
  余白が空く不具合があった（横向き最適化ゲートが無かった）。スマホでタイトル画面を開くと
  上下に巨大な黒帯が出て、ボタンが画面中央の小さな帯にしか表示されない状態だった。
- `genpei.html` に既にあった「モバイル横画面ゲート」パターン（タッチ×縦画面のみ表示する
  `.landscape-gate` オーバーレイ＋ボタンで `requestFullscreen` → `screen.orientation.lock('landscape')`
  を試みる、失敗しても案内文自体で足りる設計）をそのまま `taihei.html` に移植した。
  `sengoku.html`/`sanguo.html` にも同種のゲートがあるが、genpei の実装が taihei と
  同じ GameKit.Engine(1440×810) 構成で一番近かったため、そちらを踏襲した。

### 学び（TAIHEI_DEBUG ブリッジの追加漏れ）

検査スクリプト（`verify-taihei-boot.mjs`、新設）を書く際、`window.TAIHEI_DEBUG.buildState` を
直接呼ぼうとして `no-buildState` で落ちた。実際の実装は `buildState` がトップレベル関数ではなく
`Rule.buildState`（`Rule = { ..., buildState, ... }` にまとめられている）で、`Rule` 自体は
ブリッジに載っていた。**ブリッジの記載漏れではなく検査側の呼び出し誤り**だったが、
「トップレベル関数だと思い込んで直接呼ぶ」は sanguo/sengoku 検査でも起こり得る典型的な
誤診パターンなので、次に検査を書くときはまずブリッジのキー一覧を確認してから関数を叩くこと。

### 動的検証

`node scripts/verify-taihei-boot.mjs` を新設。ゲート表示条件（縦画面でタッチ端末のみ表示・
横画面/非タッチで非表示）に加え、以下も Playwright で実機検証し、`game.errors`
（GameKitがフレーム内で捕捉した例外）も合算して判定する:
- 起動〜陣営選択〜オープニング〜MapScene〜ターン終了1回
- 隣国への出兵→BattleSceneでヘックス合戦を最大10ラウンド消化→MapSceneへ帰還
- 3陣営（足利方・南朝方・地方勢力1家=大内氏）それぞれ最大65ターン自動進行させ、
  CutsceneScene（年代記イベント演出）・EndingScene（南北朝合一エンディング）到達を確認
  （南朝方・大内氏は17ターンでエンディング到達、足利方は59ターンでも未到達だが例外なし）

全項目PASS、例外0件。ゲームロジック・シーン遷移側に「仕様的におかしな箇所」は見つからなかった。

### 検討したが見送った項目（モバイルのタップ判定サイズ）

MapScene のコマンドバー等はデザインキャンバス 1440×810 に固定座標で配置されており、
iPhone 13横画面（実測キャンバス幅588 CSS px、スケール率0.41）では
ボタン高さが 52canvas-px × 0.41 ≈ 21 CSS px 相当まで縮む。これは `sengoku.html`/`sanguo.html`
が `UI_SCALE`／パネル拡大＋入力逆変換で対処した「固定Canvas UIのモバイル可読性対策」
（`.claude/skills/game-dev/SKILL.md`）と同種の症状ではある。
ただし姉妹作 `genpei.html`（同じ1440×810構成で横画面ゲートも既にある）も同種のUI_SCALE機構を
持たないまま運用されており、本リポジトリの現行基準では「横画面ゲートの新設」に
このスケーリング対応まで含めるのが必須という前例はないため、今回は見送った。
将来 taihei.html でモバイル操作性の指摘が出た場合は、sengoku.html の
`computeUiScale()`／パネル拡大＋逆変換パターンを移植する対応を検討する。
