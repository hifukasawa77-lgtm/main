# 2026-08-18

## 太平風雲記: モバイル横画面ゲートを追加

- `taihei.html` はモバイル縦画面で 1440×810 (16:9) の Canvas が `max-width:96vw` だけで縦に大きく
  余白が空く不具合があった（横向き最適化ゲートが無かった）。スマホでタイトル画面を開くと
  上下に巨大な黒帯が出て、ボタンが画面中央の小さな帯にしか表示されない状態だった。
- `genpei.html` に既にあった「モバイル横画面ゲート」パターン（タッチ×縦画面のみ表示する
  `.landscape-gate` オーバーレイ＋ボタンで `requestFullscreen` → `screen.orientation.lock('landscape')`
  を試みる、失敗しても案内文自体で足りる設計）をそのまま `taihei.html` に移植した。
  `sengoku.html`/`sanguo.html` にも同種のゲートがあるが、genpei の実装が taihei と
  同じ GameKit.Engine(1440×810) 構成で一番近かったため、そちらを踏襲した。

### 学び（TAIHEI_DEBUG ブリッジの追加漏れ）

検査スクリプト（`verify-taihei-boot.mjs`、新設）を書く際、`window.TAIHEI_DEBUG.buildState` を
直接呼ぼうとして `no-buildState` で落ちた。実際の実装は `buildState` がトップレベル関数ではなく
`Rule.buildState`（`Rule = { ..., buildState, ... }` にまとめられている）で、`Rule` 自体は
ブリッジに載っていた。**ブリッジの記載漏れではなく検査側の呼び出し誤り**だったが、
「トップレベル関数だと思い込んで直接呼ぶ」は sanguo/sengoku 検査でも起こり得る典型的な
誤診パターンなので、次に検査を書くときはまずブリッジのキー一覧を確認してから関数を叩くこと。

### 動的検証

`node scripts/verify-taihei-boot.mjs` を新設。ゲート表示条件（縦画面でタッチ端末のみ表示・
横画面/非タッチで非表示）と、起動〜陣営選択〜オープニング〜MapScene〜ターン終了1回の
フローを Playwright で実機検証し、`game.errors`（GameKitがフレーム内で捕捉した例外）も
合算して判定する。全項目PASS、例外0件。
