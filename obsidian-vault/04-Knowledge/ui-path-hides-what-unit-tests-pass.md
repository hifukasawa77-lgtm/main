# 単体検査とサーバ直叩きが緑でも、画面の経路で壊れる

2026-10-12、PC版 ZERO-1 に即答の枝（月齢・宇宙天気・日誌…）を足した。純粋関数の検査も、`/api/runtime` への直接の問い合わせも正しかったのに、**ブラウザでは答えがモデルの作文に差し替わっていた**。例外もエラーも出ない。

| 見つかった穴 | 原因 | 単体・直叩きで見えなかった理由 |
|---|---|---|
| 正しい即答が熟考モードの作文に置き換わる | 画面側の「答えの点検」が即答まで「出典なしで断定」と咎め、自動でやり直していた | 点検は画面が返事を受け取った**後**で動く |
| 熟考モードでは即答も日誌の記録も効かない | 熟考の口 `/api/think` が振り分け表を一度も通っていなかった | 検査は標準の口 `/api/runtime` だけを叩いていた |
| 「電気を消すと日誌に記録して」で本当に電気が消える | 声の振り分け（画面側）が家電の判定を先に見ていた | サーバの振り分けは正しく日誌と判定していた |
| 起動直後の一瞬、ロックの幕より先に会話が見える | サーバ描画の HTML は、React が設定を読むより先に表示される | 「ロック画面が出たか」だけを見ていた |

## 原則
- 枝を足したら**画面から**聞く。モードが複数あれば（標準・熟考）、**全部の口から**聞く
- 声と文字は別の振り分けを通る。**声の経路も**確かめる
- 「出たか」ではなく「出る前に何が見えたか」を数える（rAF でフレームごとに記録）
- 直したら**直す前の版でも同じ測り方**をして、違いが出ることを見る（反証）
