# Web Audio で歌声合成（フォルマント合成）を作るときの勘所

`ai-vocal-synthesizer.html`（AIボーカルシンセサイザー）の実装で実測して分かったこと。
どれも「例外は出ないのに音がおかしい」タイプの不具合で、耳で聴かずに直すには**書き出したWAVを解析して数値で確かめる**しかない。

## 1. 音源スペクトルには唇の放射特性(+6dB/oct)を必ず入れる
声帯波（グロッタルパルス）だけを再現すると倍音は約 **-12dB/oct** で落ちる。実際の声はここに
唇からの放射特性 **+6dB/oct** が乗るため、合計 **約 -6dB/oct** になる。
これを忘れると F2/F3 が F1 より 40dB 近く沈み、**どの母音も同じ「あ」に聞こえる**。

- 誤: `imag[n] = n ** -(2.3 - 0.95*bright)`（-12dB/oct 相当）
- 正: `imag[n] = n ** -(1.35 - 0.50*bright)`（-6dB/oct 相当）
- 実測: 修正前は い/う の帯域プロファイル差 L1=0.005（判別不能）→ 修正後は各母音の
  F2 ピークが表の値と誤差 0〜8% で一致し、最も近い母音ペアでも 10.9dB 離れた

## 2. 並列フォルマント合成は「音符ごとに音量が跳ねる」
帯域フィルタのQを `f/帯域幅` で素直に計算すると F1 が鋭くなりすぎ、**基音がたまたま F1 に重なった
音符だけ 5 倍大きく鳴る**（実測: 音符間の音量差 max/min = 5.0x）。

対策の組み合わせ:
- 帯域幅を歌声向けに広げ、Qを `clamp(f/bw, 1.1, 6.0)` で頭打ちにする
- **合成前に実効音量を見積もって正規化する**。倍音 n の振幅 `n^-tilt` と4本の帯域フィルタの
  振幅応答 `1/√(1+Q²(f/fc - fc/f)²)` を掛けて二乗和を取れば、鳴らす前にその音符の音量が分かる。
  基準値との比を音符ゲインに掛ける（実測: 音量差 5.0x → 1.14x）
- 子音ノイズにこの補正をそのまま掛けると子音だけ暴れるので `√補正` に留める

## 3. 幅の広い Canvas は CSS Grid の列を突き破る
`grid-template-columns: 340px 1fr` の `1fr` は最小幅が **min-content** なので、
ピアノロールのような広い Canvas を置くと列がコンテナごと広がり、要素の
`getBoundingClientRect().x` が**負**になる（＝ページ全体が横に溢れる）。
Playwright のクリックが画面外に落ちて「操作しても何も起きない」形で表面化した。

- 対策: `grid-template-columns: 340px minmax(0,1fr)` ＋ `.grid > * { min-width: 0 }`
- 検出: `document.documentElement.scrollWidth > window.innerWidth` を検査に入れる

## 4. 検証は「例外0件」では全く足りない
このツールは最初から最後まで pageerror 0 件のまま、上の3つの不具合を全部抱えていた。
音を扱うページでは以下を機械検査する:

- WAVを書き出して**自己相関でF0を測り**、楽譜の音高と cent 単位で突き合わせる
- 音符ごとのRMSを出して**音量のばらつき（max/min）**を見る
- 倍音の振幅から音源の傾き `n^tilt` を割り戻して**フォルマントのピーク周波数**を推定し、
  設計値と比べる（母音が作り分けられている証拠になる）
- ピーク値とクリップサンプル数（|x|>0.999）で音割れを確認する

## 5. 音声からのメロディ採譜（YIN）で効いた／効かなかったこと
`ai-vocal-synthesizer.html` に「再生中の曲を取り込んで歌わせる」機能を足したときの実測。

- **伴奏つきの曲は、広い帯域で追うとほぼ確実にベースを拾う**。既知メロディ＋伴奏で計測すると
  80–1000Hz では音高一致 1/14、150–1200Hz では 14/14。既定は主旋律の帯域(150–1200Hz)を先に試し、
  有声フレーム率が低いときだけ低域(80–600Hz)へ落とす二段構えにした
- **同じ音高が続く音符は音高だけでは切れない**。子音のアタック＝2kHz以上の高域エネルギーの
  立ち上がり（フラックスの局所ピーク）で区切ると、伴奏つきでも安定して正解した
- **音量の谷での分割は「浅い谷まで拾う」と逆効果**。谷の深さを実測すると中央値0.97・音符境界でも
  0.7〜0.85しかない。しきい値を0.42→0.72に緩めたら伴奏つきの一致が 14/14 → 1/14 に悪化した
  （細切れの区間がベースを拾うため）。取りこぼしは手で直せるが、誤検出は連鎖するので深い谷に限定する
- **テンポ推定は 1.5倍・2倍が同点になる**（108BPMの旋律が162BPMと判定される）。
  グリッド誤差は平均でなく**中央値**で評価し、ほぼ同点の候補からは一般的なテンポ帯(110前後)に
  近いものを選ぶと安定した
- **合成音を入力にした検証は毎回結果が変わる**（合成側のノイズが乱数のため）。1回の計測で
  良し悪しを判断せず、同じ条件を3回まわして安定性を見ること

## 6. `hidden` 属性は `display:flex` に負ける
`<div hidden>` でも CSS 側に `.recbar{display:flex}` があると表示されてしまう。
`el.hidden === true` を見るテストは通るので、**スクリーンショットを見るまで気づけない**。
`.recbar[hidden]{display:none}` を明示すること。
