# 手で更新する登録簿は、黙ってずれる

「機能を足したら登録簿にも足す」という決まりは、**書いても守られない**。
書いた本人でも忘れる。しかも登録簿は**足りなくても緑のまま**なので、誰も気づかない。

## 実例（2026-09-14・ZERO-1 デスクトップ版）

`scripts/doctor.mjs` の `TRACKED_FEATURES` は、`ZERO-1診断.cmd` が
「その機能が、いま動いている版に入っているか」を答えるための登録簿。

数えたら **8件しか登録が無く、直近に足した9つの機能が丸ごと漏れていた**。

決まりは2か所に書いてあった:
- `docs/開発の注意.md` §2「機能を足したら `TRACKED_FEATURES` にも足す」
- `doctor.mjs` のコメント「★ここを足していなかったせいで…**必ずこの登録簿にも足す**」

**その注意書きを書いた本人が、9回続けて忘れている。**

同じ根で `README.md` の「現在できること」からも同じ9機能が漏れていた。
登録簿が2つあれば、2つともずれる。

## なぜ気づけないか

登録が足りないことは**何も壊さない**。検査は緑、画面も動く。
壊れるのは「診断が答えられない」という、**使う人が困ったその瞬間**だけ。
それまでは完全に無症状。

## 決まり

- **「忘れないようにする」で終わらせない。忘れたら落ちる形にする。**
  ZERO-1 では `tests/tracked-features.test.mjs` が、
  設定パネル（＝利用者から見える機能の単位）を1枚足したら必ず落ちる
- **免除は1枚ずつ・理由つき**（[[0036-exemptions-are-per-line]] の適用）
- **目印は「画面に出る文字」にする。コメントの中の文字を目印にしない。**
  故障注入でここがすり抜けた——コメントの文字列を認めると、
  画面に出ていないのに診断が「反映済み」と答える。**嘘をつく診断は、診断が無いより悪い**

## 縛らなかったもの（これも判断のうち）

README を機械検査で縛るのは**やめた**。目印はUIの文言（エラーメッセージ等）で、
README に出したい言い回しとは別物。無理に一致させると、どちらの文章も歪んで
**誤検知の出る検査**になる。代わりに、登録漏れで鳴る検査の**失敗メッセージ**へ
「README にも1行足す」と書いた——**ちょうどその瞬間に読まれる場所**に置くのが効く。

→ `zero-1-local-ai/docs/開発の注意.md` §2 と `CLAUDE.md`、および
   `tests/tracked-features.test.mjs` へ昇格済み（2026-09-14）
